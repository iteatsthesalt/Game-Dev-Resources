8-Way Sprite Rig

A hidden 3D skeleton drives the game. Each frame, the sprite picks its row from the angle between the character and the camera, and its column from the skeleton's clip time. Gear is baked into the atlas; anything held in a hand rides on a projected 3D bone. The same rig works for a beast on four legs, a tree in the wind and a chest on its hinge. Cinderdeep's heroes walk on this skeleton, and its creatures, trees and chests follow the same rules. Walk the result around the playground, then take the atlas with you.

Every cell was rendered from the same skeleton by a virtual camera at that row's angle, then pixel-thresholded and outlined. With mirroring on, rows past 180° are never sampled: the runtime flips the row on the other side and shifts the frame by half a cycle so the stride stays on the correct leg.

Runtime wiring

// Runs every frame, after the 3D skeleton has animated.
function spriteFor(skel, camYaw, state) {
  const rel = wrap360(skel.facingYaw - camYaw);     // 0° = we see its back
  state.dir = pickDir(rel, state.dir, HYST, DIRS);  // sticky near sector edges
  const clip = CLIPS[skel.clip];
  let col = Math.floor(skel.clipTime * FRAMES);     // clipTime is 0..1
  let row = state.dir, flip = false;
  if (MIRROR && clip.symmetric && row > DIRS / 2) {
    row = DIRS - row; flip = true;                  // reuse the row facing the other way
    col = (col + clip.mirrorShift) % FRAMES;        // walk: half a cycle swaps the leading leg
  }
  return { sheet: clip.sheet, row, col, flip };
}

function pickDir(rel, cur, hyst, dirs) {
  const step = 360 / dirs;
  const snap = Math.floor((rel + step / 2) / step) % dirs;
  if (cur == null) return snap;
  return Math.abs(wrap180(rel - cur * step)) <= step / 2 + hyst ? cur : snap;
}

// Props: project the hand bone with the SNAPPED angle and frame, so the prop
// sticks to the drawn hand; draw it behind the sprite when the hand is farther
// from the camera than the chest.
const snapped = skel.poseAt(col / FRAMES);
const hand = project(snapped["hand.R"], state.dir * (360 / DIRS));
const behind = hand.depth > project(snapped.chest, state.dir * (360 / DIRS)).depth;

How the pieces connect

  1. The skeleton is the truth. Movement, animation state, hitboxes and bone positions all live on the 3D rig. The sprite never drives gameplay.
  2. Row from angle. Subtract the camera's yaw from the character's yaw, then quantize to sectors. Hysteresis keeps the row from flickering when the angle sits on a sector edge.
  3. Column from clip time. Each clip is baked at even steps, so floor(t × frames) keeps sprite and skeleton in lockstep through blends and speed changes.
  4. Gear is baked, props are attached. Helmets, hoods, capes and packs move with the body, so they go into the atlas. A sword or a torch changes during play, so it is drawn from the projected hand bone and sorted against the chest.
  5. Mirroring is free art, sometimes. A flipped walk is the same walk half a cycle later, so fewer than half the rows need baking. An attack swings one arm: flipped, it swings the other, so asymmetric clips bake every row.
  6. Anything with joints. A beast's four legs, a tree's trunk and canopy, a chest's hinged lid: only the skeleton and the painter change. Rows still come from the angle and columns from clip time. Whatever can be flipped without lying (a trot, a shut lid) mirrors; a tree in a one-way wind cannot.
  7. Export the contract. The JSON lists each clip's rows, which directions flip, and where the hands are in every cell, so a game engine can attach props without the skeleton.
