# Byways 05: AI Search and AI Team Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Let people add their own AI keys, test them, pick a model, and run AI Search with one model or an AI team, with grounded links only, hard cost caps and a visible cost line.

**Architecture:** Every provider goes through a small `fetch` adapter in `src/core/ai/adapters/` (no vendor SDKs). A data table (`providers.js`) says how to reach each provider. `search.js` builds a brief, runs one adapter or the team (`team.js`), drops every link the provider's own search metadata does not hold (`grounding.js`), checks the budget (`cost.js`), and injects the finds into the engine. The UI adds Settings → AI, a first-run AI step, a cost line and AI badges on cards.

**Tech Stack:** JavaScript ES2022 modules, no framework, no bundler. `node:test` for unit tests, `@playwright/test@1.63.0` (Chromium) for end-to-end tests. Web Crypto (`crypto.subtle`) for PKCE and the passphrase lock.

**Spec:** `docs/superpowers/specs/2026-11-11-byways-design.md` (§12 all, §5.6 step 4, §15.1 AI rows, §21 items 2–3). Research notes: `docs/superpowers/specs/byways-research/claude-browser.md`, `other-providers.md`, `critic.md`. Shared contract: `docs/superpowers/plans/2026-11-11-byways-00-overview.md`.

## Global Constraints

- Every rule in the overview's "Global constraints (every plan)" and "Working conventions" applies. The lines below are the ones that bite this plan.
- "Every provider goes through small `fetch`-based adapters, with no vendor SDKs, so the code is the same in all three versions." (§12.1)
- Claude: `POST https://api.anthropic.com/v1/messages` with `x-api-key`, `anthropic-version: 2026-10-21`, `anthropic-dangerous-direct-browser-access: true` and `content-type: application/json`. "Never send `credentials: 'include'`." (§12.3)
- Claude body: `output_config.effort` set to `low`; adaptive thinking; "**no** `temperature`, `top_p` or `top_k`, which return a 400 on this API version." (§12.3)
- Claude tools: `web_search_20260209` with `max_uses: 3`, plus `allowed_callers: ['direct']` when the model's `capabilities.code_execution.supported` is false; `report_finds` with `strict: true`, `additionalProperties: false`, and `tool_choice: auto`. (§12.3)
- "On `pause_turn`, send the paused content back with the same tools and the `container` id, at most 5 times." (§12.3)
- Cost: "`usage.server_tool_use.web_search_requests × $0.01`, plus tokens times the model price. Prices per million tokens (input/output): Opus 5.5 $4/$20, Sonnet 5.5 $2/$10, Haiku 5.5 $0.10/$0.50." (§12.3)
- "A link from AI is shown only if **all** of these are true": it is in the provider's own search metadata, and it is `http(s)`, not blocked, not already seen, and passes the liveness check. (§12.4)
- Gemini: "Native `generateContent` with `google_search`, then a second call that formats the result as JSON. Never the OpenAI-compatible endpoint." (§12.2)
- OpenRouter: "The `openrouter:web_search` tool (engine `auto`, `max_results 5`, `max_uses 2`)." (§12.2)
- Team: `Promise.allSettled`; "45 s for members that search and 20 s for the Captain"; merge "by normalised URL (§14.1)"; the Captain "returns `{order:[candidateId], why:{id:text}}` with a strict schema, and may only reference ids it was given." (§12.6)
- Caps: "$0.50 by default and adjustable" per run; "50 searches per provider per day"; "$2.00 a day in total, adjustable"; "AI results are cached per query for 7 days"; unknown prices show "price unknown". (§12.7)
- Keys: "A key is sent only to its own provider's host." "AES-GCM, using a key derived by PBKDF2-SHA-256 (600,000 iterations)." Never in exports (unless chosen), share links or logs. (§12.8)
- §15.1: AI calls go "Only [to] the providers you set up, with your query, your tags and recent domains."
- Model identifiers appear only in `providers.js`, `models.js`, their tests, fixtures and the copy that shows them as data. Never in commit messages or code comments.
- Strict tool schemas may not use `minLength`, `maxLength`, `minItems`/`maxItems` or numeric bounds (claude-api reference: strict mode rejects them). Limits are stated in `description` text and enforced in `cleanFinds`.

## Review Focus

1. **Near-miss URLs from the model.** A model reports `https://WWW.Example.org/a/?utm_source=x#top` while search returned `https://example.org/a`. A person expects the find kept, and a link that only the model claims to know dropped. Pinned by `filterGrounded matches by normalised URL and drops ungrounded links` (Task 5).
2. **Hostile text in search results.** A result title holds `<img src=x onerror=alert(1)>` and a 900-character "why". A person expects plain text, cut to length, and no `javascript:` link. Pinned by `cleanFinds cuts lengths, filters tags and drops non-http urls` (Task 4) and the e2e `AI find text renders as plain text` (Task 17).
3. **Repeated paid searches.** Hands-free "search for …" repeated, or the same query typed twice. A person expects the second identical query to cost nothing, and the 51st search of the day to stop with a clear reason. Pinned by `aiSearch serves a repeated query from the 7-day cache with no network` and `aiSearch stops at the daily search cap` (Task 15).
4. **A key sent to the wrong host.** A custom or local base URL, or a redirect, points somewhere else. A person expects the key never to leave its provider's host. Pinned by `aiFetch refuses to send a key to another host` (Task 2) and `mapAiError never repeats key text from the body` (Task 2).
5. **Keys locked at search time.** The passphrase lock is on and the app was reloaded. A person expects "Unlock your keys in Settings → AI to search." and keyword search instead, with no provider call. Pinned by `aiSearch with a locked keyring makes no provider call` (Task 15).

- [ ] **Step 3: Implement `src/core/ai/errors.js`**

`mapAiError` checks, in this order: an `AbortError` → `aborted`, "Stopped."; a `TypeError` → `unreachable` with the message and hint in the test, and `setupText = LOCAL_SETUP[providerId] ?? null`; 403 on `ollama` → the Ollama message; 401/403 → `key`; 429/402 → `quota`, adding " Try again in N s." when `parseRetryAfter` gives a value (N rounded up to whole seconds); 400 on `openai` whose body matches `/verif/i` → `verify`; 400 on `anthropic` whose body matches `/web search/i` and `/not enabled|disabled/i` → `search-off`; anything else → `http`, "<name> returned an error (<status>)." Messages are built only from the provider name and numbers, never from the body. `aiFetch` checks `keyHostOk` first when `keyHeader` is set and `init.headers[keyHeader]` is present, sets `credentials: 'omit'`, passes `signal`, retries once on a `TypeError`, maps a status ≥ 400 with `mapAiError` (reading the body as text) and returns `await res.json()`.

### Task 3: Cost, run cap and daily budget

**Files:**
- Create: `src/core/ai/cost.js`
- Test: `tests/unit/ai/cost.test.js`

**Interfaces:**
- Consumes: `priceFor`, `getProvider` (Task 1); `openStore`, `memoryBackend` (Plan 01, `store/db.js`); `fakeClock`, `utcDate` (Plan 01, `util/clock.js`); `DEFAULT_SETTINGS` (Plan 01).
- Produces:
  - `CAUTIOUS_PRICE = {in: 3, out: 15, searchUsd: 0.03}`; any `null` field of a price, or a `null` price, uses the matching cautious field.
