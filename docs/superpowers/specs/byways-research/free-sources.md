## free-sources
- [verified] Wikipedia random article: GET https://{lang}.wikipedia.org/api/rest_v1/page/random/summary (it redirects to page/summary/{title}). Fields: title, description, extract, extract_html, thumbnail.source, originalimage.source, content_urls.desktop.page, type (for example 'disambiguation'), coordinates. No key.
  => The Fate adapter for Wikipedia calls page/random/summary. Skip type==='disambiguation'. For image-first cards, re-roll when there is no thumbnail (at most 3 tries).
- [verified] The Wikipedia REST API (RESTBase) sends access-control-allow-origin: * and allows the request header api-user-agent.
  => Call it directly from the PWA. Send a generic Api-User-Agent such as 'Byways/1.0 (+repo URL)', with no user email.
- [verified] The MediaWiki Action API (w/api.php) returns Access-Control-Allow-Origin: * without credentials only when the request has origin=*. Keyword search: w/api.php?action=query&generator=search&gsrsearch=Q&prop=pageimages|extracts|info&inprop=url&piprop=thumbnail&pithumbsize=640&exintro=1&explaintext=1&format=json&origin=*
  => The shared fetch helper adds origin=* to every MediaWiki Action API URL (Wikipedia and Commons) and never sends credentials.
- [verified] Per-wiki feed: GET https://{lang}.wikipedia.org/api/rest_v1/feed/featured/YYYY/MM/DD returns tfa (today's featured article, a summary object), mostread.articles[], image (picture of the day: title, thumbnail.source, image.source, file_page, artist, license.type, description), news[] and onthisday[]. There is also feed/onthisday/{type}/MM/DD.
  => Daily Fate can be built on date-keyed content: the UTC date picks the featured article, the picture of the day or an on-this-day item. Every user then sees the same pick without a shared server.
- [likely] The api.wikimedia.org Feed and Core routes are being deprecated gradually from July 2026. The per-wiki rest_v1 paths are the equivalents.
  => Never hardcode api.wikimedia.org. Use {lang}.wikipedia.org/api/rest_v1/... Keep each endpoint behind an adapter so a RESTBase sunset only means swapping in Action API calls (generator=random&prop=extracts|pageimages).
- [likely] From 2026 Wikimedia enforces global per-minute rate limits by client class and returns HTTP 429 when they are exceeded. The numbers are experimental, and sources conflict: 200/min for unauthenticated browser traffic on mediawiki.org, 10/min for 'unidentified' clients per a GitHub issue.
  => Cache summaries in IndexedDB, prefetch at most 2-3 cards ahead, honour Retry-After and back off on 429. Budget at most about 10 requests per minute per source by default.
- [likely] For Rabbit Hole on Wikipedia, CirrusSearch supports srsearch=morelike:<Title> (list=search or generator=search).
  => The Wikipedia adapter implements more-like-this as generator=search&gsrsearch=morelike:<title>&origin=*.
- [likely] Wikimedia Commons random image: w/api.php?action=query&generator=random&grnnamespace=6&grnlimit=1&prop=imageinfo&iiprop=url|mime|extmetadata&iiurlwidth=1024&format=json&origin=*. Fields: imageinfo[0].thumburl, descriptionurl, mime, extmetadata.ObjectName/ImageDescription/Artist/LicenseShortName. Search uses generator=search&gsrnamespace=6&gsrsearch=Q.
  => Filter to raster mimes and a minimum width. Sanitize the extmetadata HTML (Artist and ImageDescription hold HTML) before rendering, and always show the licence and author on the card.
- [verified] Met Collection API: no key, and the docs ask clients to stay under 80 requests per second. GET /public/collection/v1/objects/{id} returns title, primaryImageSmall, primaryImage, objectURL, artistDisplayName, objectDate and isPublicDomain.
  => Use primaryImageSmall for cards and objectURL as the link. Only use isPublicDomain=true items for images.
- [verified] The Met's /public/collection/v1/search was deprecated and retired on 2026-10-01. The replacement /public/collection/v1.1/search accepts the same filters (q, hasImages, isHighlight, departmentId, ...) plus offset and limit, does not require q, and pages through at most 10,000 results.
  => Use only v1.1. Fate = v1.1/search?hasImages=true&isPublicDomain=true&limit=1&offset=random(total), then objects/{id}.
- [unverified] Met API CORS status is unknown. API directories list CORS: No, there is no official statement, and the Met is not open source.
  => Ship Met as 'probe' tier: a runtime CORS self-test. If fetch throws a TypeError in the PWA, use it only through the extension or Android native fetch, or through a GitHub Actions snapshot.
- [verified] Art Institute of Chicago API: no key, anonymous clients are throttled to 60 requests per minute, search pagination is capped at 10,000 results, and scrapers are asked to keep to 1 request per second. The docs ask for an AIC-User-Agent header because browsers forbid setting User-Agent. Search: https://api.artic.edu/api/v1/artworks/search?q=Q&query[term][is_public_domain]=true&fields=id,title,image_id,artist_display,thumbnail&limit=N&page=P
  => Send the AIC-User-Agent header as 'Byways (+repo URL)'. Fate picks a random page within the first 10,000 public-domain results. Use the fields= parameter to keep responses small.
- [verified] AIC API CORS is open: config/cors.php has paths ['ai/*','api/*'], allowed_origins ['*'] and allowed_headers ['*'].
  => The PWA can call api.artic.edu directly, including the custom AIC-User-Agent header, which triggers a preflight that is allowed.
- [verified] AIC image URL pattern: {config.iiif_url}/{image_id}/full/843,/0/default.jpg, where iiif_url is https://www.artic.edu/iiif/2 (IIIF Image API 2.0).
  => Build the image URL from config.iiif_url in the response rather than a hardcoded base. Use 843 wide for cards and smaller sizes for the feed.
- [likely] Since about January to June 2026 the AIC IIIF image host (www.artic.edu) answers many non-browser and datacenter clients with a Cloudflare managed challenge (HTTP 403). An older issue also reports that the images no longer send CORS headers.
  => Treat AIC images as unreliable. On img onerror, fall back to thumbnail.lqip (an inline base64 placeholder) or skip the item. Never draw AIC images to canvas. Rank AIC below fully reliable sources.
- [verified] Cleveland Museum of Art Open Access: GET https://openaccess-api.clevelandart.org/api/artworks/?q=Q&cc=1&has_image=1&limit=N&skip=M. Fields: title, url (museum page), images.web.url (also print and full), creators, creation_date, creditline, type, share_license_status ('CC0'). No key.

- [unverified] Cleveland API CORS and rate limits are not documented.
  => Ship Cleveland in the 'probe' tier with a runtime CORS self-test and a conservative limit of 1 request per second.
- [verified] NASA APOD: GET https://api.nasa.gov/planetary/apod?api_key=KEY with date=YYYY-MM-DD, count=N (random dates, N at most 25), start_date/end_date and thumbs=true.   => Fate: one count=10 call fills a local queue of 10 random APODs. Daily Fate can use date=today (UTC). If media_type is video, use thumbnail_url for the card. Show the copyright field when present.

RISKS:
- The web search budget ran out partway through, so several facts depend on search-engine summaries of official pages rather than direct reads: Met v1.1 details, NASA DEMO_KEY figures, the LoC limit, Open Library rates, Marginalia public-key behaviour and the Wikimedia 2026 limits. Re-check these when the network allows.
- CORS is still unverified for the Met, Cleveland, NASA Images, LoC, Smithsonian, Wiby and the Kagi feed, and HN Algolia is only 'likely'. Direct fetches to every one of these hosts were refused (403) by this machine's proxy, so no live response headers were captured except from api.github.com and raw.githubusercontent.com.
- AIC's IIIF image host has served Cloudflare challenges since 2026. Hotlinked AIC images may fail in some browsers or networks even though the JSON API works.
- Met v1/search was retired on 2026-10-01. Any copied tutorial code that uses it will break.
- Wikimedia's 2026 rate limits are experimental and may tighten. api.wikimedia.org routes are being deprecated, and further RESTBase sunsets (page/random, feed) could follow.
- The Openverse anonymous defaults in code (5/hour, 100/day) are too low for auto-advance, so Openverse is only usable with user-registered client credentials.
- The Marginalia public key is shared worldwide and often returns 503. The NASA DEMO_KEY allows only 50 calls per day per IP and is shared behind any common NAT.
- The Kagi /smallweb/api/random public path is inferred from the URL_PREFIX env var plus the feed URLs and was not observed live. The raw lists are the verified fallback, and smallweb.txt currently contains a junk first line.
- itch.io, Game Jolt and Newgrounds give the PWA no CORS-readable data. Live indie-game discovery in the PWA depends on GitHub, HN Show HN and the Kagi ?gh mode unless a GitHub Actions snapshot is added.
- GitHub's unauthenticated search limit (about 10/min) could not be observed here because this machine's proxy authenticates requests (it showed 30/min).
- The Api-User-Agent and AIC-User-Agent headers go to third parties. They should name the app and the public repo only, never the user's email or name.
RECS:
- Ship these 10 sources, ranked by reliability then fun: (1) Wikipedia: REST random/summary, Action API search with origin=*, and the featured feed for Daily Fate; CORS verified. (2) Kagi Small Web: /smallweb/api/random, with the raw GitHub lists as an offline fallback; the purest 'stumble'. (3) Wikimedia Commons: random and searched images, licence metadata, CORS verified. (4) iNaturalist: CC-licensed nature photos, CORS verified, 1 req/s. (5) Hacker News Algolia with Show HN: 10k/hr, indie projects and games. (6) NASA APOD with count=10 random batches, plus NASA Images for search; uses the user's api.data.gov key, with DEMO_KEY as fallback. (7) Marginalia: indie-web keyword search plus /site/{domain}/similar for Rabbit Hole; CORS verified. (8) GitHub topic search for indie and jam games: CORS verified, cached for 1 hour, optional PAT. (9) Open Library: CORS verified on .json, covers CDN. (10) Art Institute of Chicago: CORS and limits verified, but with image onerror fallbacks because of the Cloudflare risk.
- Key-unlocked extras, since the user can enter keys: Europeana (free key, CORS verified), Openverse (registered client credentials; CORS verified; anonymous use is too limited), and Smithsonian (the same api.data.gov key as NASA; enable only after the CORS probe passes). Keep keys in device storage only, never in share links or synced collections, with one Settings field per provider.
- Probe tier: the Met (v1.1 only), Cleveland, LoC, NASA Images and Wiby. At first run and once a day, run one small GET per source. If it throws a TypeError, mark the source 'privileged-only' and hide it in the PWA but keep it in the extension and Android builds.
- Give every source adapter the same interface: random(), search(q), more(item), plus metadata {cors, keyMode: none|demo|optional|required, rateLimit, licenceField}. Each adapter returns normalised Find objects {id, source, title, description, imageUrl, linkUrl, licence, attribution, author}.
- Put a per-source token bucket in the core, seeded from the facts above (Met 80/s, AIC 60/min, iNat 1/s, Open Library 1/s, LoC 10/min, APOD by key tier, GitHub 10/min for search, Wikimedia about 10/min by default). Back off on 429 and 503 using Retry-After, cache responses in IndexedDB, and prefetch at most 3 finds ahead so hands-free auto-advance cannot drain quotas.
- Daily Fate (same for every user): use the UTC date with date-native content first, namely Wikipedia feed/featured/{date} (tfa or the picture of the day) and APOD date={date}. For other sources, seed a PRNG with the date only over stable ID lists. Random-offset queries into live collections shift as items are added, so they would not be identical across users.
- Indie games for the PWA without a server: use GitHub topics, Show HN with query 'game', and the Kagi ?gh mode live. Optionally add a scheduled GitHub Actions workflow in the same repo that turns itch.io .xml feeds (and any CORS-blocked probe sources) into same-origin /data/*.json on Pages. The extension and Android builds can read the itch.io feeds directly through privileged fetch.
- Licence handling: always render the attribution and licence (Openverse attribution, Commons extmetadata LicenseShortName/Artist, iNat license_code, Cleveland share_license_status, Met isPublicDomain, Wikipedia CC BY-SA with a link back). Only show images from sources or items flagged open or public domain. Sanitize every HTML field (extract_html, Commons extmetadata, HN story_text) before rendering.
- Send identification headers where they are welcomed and CORS allows them (Api-User-Agent for Wikimedia, AIC-User-Agent for AIC), set to 'Byways/<version> (+public repo URL)'. Never include user details.
