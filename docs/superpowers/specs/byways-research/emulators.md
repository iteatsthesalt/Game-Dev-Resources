## emulators
- [verified] js-dos latest is 8.5.3 on npm (package name js-dos, published 2026-10-07, license GPL-2.0). It is a single package that holds the player UI plus all emulator backends.
  => Pin js-dos@8.5.3 in a single versions manifest in the shared core. Treat any upgrade as a deliberate change.
- [verified] js-dos page files and sizes (bytes). Always loaded: dist/js-dos.js 323,688, dist/js-dos.css 118,628 and dist/emulators/emulators.js 90,630. Default 'dosbox' backend: wdosbox.js 114,763 + wdosbox.wasm 1,459,535. 'dosboxX' backend (Win9x/3dfx): wdosbox-x.js 285,604 + wdosbox-x.wasm 8,045,933. Zip helper: wlibzip.js 72,957 + wlibzip.wasm 112,483. No BIOS file is needed. Unpacked package size is 41.4 MB.
  => Default to the light 'dosbox' backend (about 1.6 MB). Offer DOSBox-X only as an opt-in 'Windows 9x mode' (about 8.3 MB).
- [verified] By default js-dos 8.5.3 loads its emulator files from the unpinned URL https://v8.js-dos.com/latest/emulators/ unless the pathPrefix option is set. It loads them by injecting <script src=pathPrefix+'emulators.js'>.
  => Always pass pathPrefix: 'https://cdn.jsdelivr.net/npm/js-dos@8.5.3/dist/emulators/' (or a self-hosted copy). Otherwise the wasm silently tracks 'latest' from a third-party host.
- [likely] jsDelivr pinned pattern for js-dos: https://cdn.jsdelivr.net/npm/js-dos@8.5.3/dist/js-dos.js and .../dist/js-dos.css. The package's own sample page uses https://cdn.jsdelivr.net/npm/js-dos@8.4.1/dist/js-dos.css.
  => Use the /npm/<pkg>@<exact-version>/<path> form everywhere and smoke-test each URL in CI or a manual checklist.
- [verified] js-dos minimal API: window.Dos(element, options) returns DosProps. Options read in 8.5.3 include url, dosboxConf, jsdosConf, initFs, pathPrefix, backend ('dosbox'|'dosboxX'), workerThread, autoStart, kiosk, theme, mouseCapture, softKeyboardLayout, volume, fsChanges and opfsRoot. DosProps exposes save(), stop(), setPaused(), setVolume() and getLocalChanges().
  => Wrap js-dos in a small adapter: start(file) -> props, then pause/stop/save. Voice commands map to setPaused, save and stop.
- [verified] js-dos 'url' mode fetches the bundle with fetch(url,{cache:'no-store'}), so a blob: URL from URL.createObjectURL(file) works. The file must be a .jsdos bundle or a .zip. A zip without a .jsdos/dosbox.conf makes js-dos show its own config screen. The built-in picker says 'Select jsdos/zip file to start'.
  => For a picked file, call Dos(el,{url: URL.createObjectURL(file), pathPrefix, fsChanges:{urlToKey}}). Accept .zip/.jsdos only, or zip a lone .exe/.com in the browser first.
- [verified] js-dos alternative with no URL: pass dosboxConf (string) plus initFs, where InitFs = Uint8Array (zip) | {path, contents: Uint8Array} | DosConfig | string, or an array of these. js-dos then boots without fetching anything.
  => Use this path for 'run this single .EXE' (generated autoexec). It does not support saving (see next fact).
- [verified] js-dos saves only in 'url' mode. Saves are filesystem diffs (persist(true)) written to OPFS at <opfsRoot>/saves/<key>, where key = fsChanges.urlToKey(url) ?? url + '.changes'. The built-in file-picker path and the dosboxConf path have no bundleChangesUrl, so save() returns false. In 8.4.0 OPFS replaced IndexedDB. fsChanges.push/pull/delete hooks allow custom storage.
  => A blob: URL changes every session, so ALWAYS supply fsChanges.urlToKey returning a stable key (for example 'dos-'+sha256(file)). Otherwise the user's saves are orphaned. Consider fsChanges.push/pull to keep saves in the app's own IndexedDB so they show up in the app's export/backup.
- [verified] In url mode js-dos also caches every fetched bundle in OPFS (<opfsRoot>/caches/bundles), keyed by the sanitized URL. A new blob: URL each launch therefore stores a fresh copy of the user's game each time.
  => After a session, delete the 'blob_*' entries under navigator.storage.getDirectory()/jsdos/caches/bundles, or set a per-app opfsRoot and prune it. Show storage use in the Lab settings.
- [verified] js-dos does not use SharedArrayBuffer. No js-dos 8.5.3 JS file mentions SharedArrayBuffer or crossOriginIsolated. Worker mode (on by default) builds the Worker from a fetched blob: URL.
  => DOS runs on plain GitHub Pages with no COOP/COEP. Prefer js-dos over EmulatorJS's dosbox_pure core, which needs threads. Blob workers need worker-src blob: in any CSP the app sets.
- [verified] js-dos touch support: mobileControls and soft-keyboard settings exist (nipplejs dependency). The README says 'Mobile support (v8 - WIP, v7 - production)'. js-dos calls navigator.keyboard.lock(['KeyW','Escape']) when it is created.
  => Mark DOS on phones 'experimental'. Provide an on-screen exit/pause button and a voice 'stop', because Esc can be captured in fullscreen.
- [verified] EmulatorJS is on npm as @emulatorjs/emulatorjs (latest 4.2.3, GPL-3.0, last published 2025-07-05). The unscoped 'emulatorjs' package was unpublished. A GitHub v4.3.0-pre pre-release exists, labelled not stable. It rewrote subsystems (ES modules) and its cores are incompatible with other versions.
  => Pin 4.2.3 (the stable channel). Never mix core versions with the loader version. Revisit when 4.3.0 is marked stable.
- [verified] The @emulatorjs/emulatorjs npm package does NOT contain cores and does NOT contain emulator.min.js or emulator.min.css. loader.js first requests emulator.min.js, logs an error, then falls back to the unminified data/src/*.js. Sizes: loader.js 7,594, src/emulator.js 341,775, emulator.css 33,532, shaders.js 139,565, socket.io.min.js 46,831, nipplejs.js 20,259 and other helpers under 20 KB. Archive helpers (extractzip.js 196,199, extract7z.js 280,155, libunrar.wasm 173,799) load on demand.
  => Either use the official CDN data folder (minified, with cores) or self-host the GitHub release zip. With jsDelivr npm, expect one 404 and console noise per launch.
- [verified] EmulatorJS cores are separate npm packages: @emulatorjs/core-<core>@4.2.3 (umbrella @emulatorjs/cores). Each holds <core>-wasm.data, <core>-legacy-wasm.data (WebGL1), <core>-thread-wasm.data, <core>-thread-legacy-wasm.data and reports/<core>.json. Examples: snes9x-wasm.data 1,093,765; pcsx_rearmed-wasm.data 1,039,627; ppsspp ships only ppsspp-thread-wasm.data 4,581,537 + ppsspp-assets.zip 10,873,836; dosbox_pure ships only thread variants (1.79 MB).
  => Download cores lazily, one per system, the first time the user launches that system. Show the size before downloading.
- [verified] EmulatorJS path resolution: dataPath = EJS_pathtodata. Cores load from dataPath+'cores/'+file. Any file can be redirected with EJS_paths[<basename>] (for example 'snes9x-wasm.data', 'snes9x.json'). If the core 404s, it falls back to https://cdn.emulatorjs.org/<ejs_version>/data/cores/..., a fallback the code labels 'not officially supported'.
  => Pinned options: (a) EJS_pathtodata='https://cdn.emulatorjs.org/4.2.3/data/' (the versioned path is implied by the code; not fetched here), or (b) jsDelivr: EJS_pathtodata='https://cdn.jsdelivr.net/npm/@emulatorjs/emulatorjs@4.2.3/data/' plus EJS_paths mapping each core to 'https://cdn.jsdelivr.net/npm/@emulatorjs/core-<c>@4.2.3/<c>-wasm.data' and reports/<c>.json.
- [verified] EmulatorJS minimal start uses page globals read once by loader.js: EJS_player (a CSS selector string), EJS_core (system or core name, e.g. 'snes','psx','gba'), EJS_gameUrl, EJS_pathtodata, plus optional EJS_biosUrl, EJS_gameName, EJS_threads, EJS_startOnLoaded, EJS_disableDatabases and EJS_forceLegacyCores. Then <script src=.../data/loader.js>. It builds a single window.EJS_emulator = new EmulatorJS(EJS_player, config).
  => Run each EmulatorJS session in its own same-origin iframe page (e.g. lab/ejs.html?sys=snes). Pass the file in by postMessage, set the globals, then inject loader.js. Tear down by removing the iframe.
- [verified] EJS_gameUrl accepts a File, Blob, ArrayBuffer or Uint8Array as well as a URL string. The whole file is read into memory (Blob.arrayBuffer()). A blob: URL string is fetched and then URL.revokeObjectURL()'d by EmulatorJS.
  => Pass the picked File object directly (window.EJS_gameUrl = file). Never reuse a blob URL after handing it over. Warn above about 500 MB on mobile because of the full in-memory copy.
- [verified] EmulatorJS systems -> cores in 4.2.3: nes (fceumm, nestopia), snes (snes9x), gb (gambatte), gba (mgba), n64 (mupen64plus_next, parallel_n64), nds (melonds, desmume, desmume2015), vb, psx (pcsx_rearmed, mednafen_psx_hw), psp (ppsspp), segaMS/segaMD/segaGG/segaCD/sega32x/segaSaturn (genesis_plus_gx, picodrive, smsplus, yabause), 3do (opera), atari2600/5200/7800/lynx/jaguar, arcade (fbneo, fbalpha2012_cps1/2), mame (mame2003_plus, mame2003), pce, pcfx, ngp, ws, coleco, amiga (puae), c64/c128/pet/plus4/vic20 (vice), dos (dosbox_pure).
  => Drive the Lab's 'pick a system' list and the file-extension auto-detect from this table. Hide 'dos' (use js-dos instead) and mark 'psp' as needing isolation.
- [verified] Only ppsspp (PSP) and dosbox_pure (DOS) REQUIRE threads. They refuse to start unless EJS_threads is true AND window.SharedArrayBuffer exists. PSP also forces WebGL2. Other cores use thread variants only if SAB exists and threads are enabled.
  => All Lab systems except PSP work without cross-origin isolation. Ship PSP as an 'advanced, isolated page' feature, or leave it out of v1.
- [likely] Which EmulatorJS systems need BIOS files: the official system docs list PS1 BIOS per region (scph5500.bin JP, scph5501.bin US, scph5502.bin EU), Sega CD bios_CD_U/E/J.bin (marked required), Saturn saturn_bios.bin, optional SMS bios, NDS BIOS only for the melonds core, and FDS disksys.rom only for Famicom Disk System. The 3DO (opera) requirement was not confirmed.
  => Add a 'BIOS shelf' where the user adds their own BIOS files, stored in IndexedDB and keyed by system. Gate Sega CD, Saturn and 3DO behind 'BIOS required'. For PS1, allow launching without BIOS but recommend adding one.
- [likely] EJS_biosUrl given as a File or Uint8Array probably throws in non-debug mode, because downloadGameFile calls assetUrl.split('/') before converting it. A plain blob: URL string avoids the throw, but an uncompressed BIOS is then written under the blob UUID instead of its real file name. A ZIP is extracted using its inner file names.
  => Pass a user BIOS as URL.createObjectURL(zipBlob), where zipBlob is a ZIP built in the browser (e.g. with fflate) that holds the correctly named file, such as scph5501.bin. Cover this with a test.
- [verified] EmulatorJS persistence uses IndexedDB. In-game battery saves live in an IDBFS mount at /data/saves (autoPersist). Save states go to the 'EmulatorJS-states' DB when 'save-state-location' is 'browser'. Caches: 'EmulatorJS-core' (cores, keyed by file name with version = report.buildStart), 'EmulatorJS-roms' and 'EmulatorJS-bios'. Saving in the browser needs EJS_gameName to be a string or a non-blob gameUrl. Hooks exist: EJS_onSaveState, EJS_onLoadState, EJS_onSaveSave, EJS_onLoadSave.
  => Always set EJS_gameName to a stable per-file id (e.g. a hash prefix plus a sanitized title) so saves reattach. Optionally mirror states into the app's own store through the EJS_onSaveState hooks for backup and export.
- [verified] EmulatorJS core caching breaks offline. If cores/reports/<core>.json cannot be fetched, buildStart becomes Math.random() and the cached core in IndexedDB never matches, so the core is downloaded again (and fails offline).
  => For offline play, the PWA service worker must cache both the core .data file and its reports/<core>.json, plus loader/src files, in Cache Storage once the core has been used.
- [verified] EmulatorJS touch support: a built-in virtual gamepad (nipplejs) appears automatically once a touch or pointerType 'touch' event is seen. The layout can be customised with EJS_VirtualGamepadSettings.
  => No custom touch overlay is needed for consoles. Make sure the app's own gesture or swipe handlers are off while a Lab iframe is focused.
- [verified] EmulatorJS loads the core's JS by creating a blob: URL script (URL.createObjectURL(new Blob([js]))). Only in debug mode or on localhost does it contact cdn.emulatorjs.org/stable/data/version.json. Netplay defaults to https://netplay.emulatorjs.org but runs only under EJS_DEBUG_XX + EJS_EXPERIMENTAL_NETPLAY.
  => Any CSP on Lab pages must allow script-src blob:. Do not set EJS_DEBUG_XX in production; it also disables core caching (this.debug).
- [likely] Many EmulatorJS/libretro cores are under NON-COMMERCIAL licenses (snes9x, genesis_plus_gx, mame2003/mame2003_plus, likely fbneo/fbalpha2012). The core npm packages carry no SPDX license field (license = 'LICENSE', 'COPYING', '' and so on) and ship no license text.
  => Fine for a free personal/friends app, but the spec must forbid ads or monetisation of the Lab. List each enabled core and its upstream license in THIRD_PARTY_NOTICES.

- [verified] coi-serviceworker 0.1.7 (MIT, last published 2023) adds COOP: same-origin, COEP (require-corp, or credentialless if coi.coepCredentialless() is true) and CORP: cross-origin to every response that passes through its fetch handler, then reloads the page once. It must be served from the page's own origin (not a CDN), cannot be bundled, needs HTTPS, does nothing where service workers are unavailable (e.g. some private modes), and returns opaque (status 0) responses unchanged. Its default enables credentialless only when neither window.chrome nor window.netscape exists.
  => It works as a GitHub Pages workaround, but it is a full service worker and conflicts with the PWA's own offline SW (one registration per scope). Do not add it as a second SW. Copy its header-injection logic into Byways' single SW and apply it conditionally.
- [likely] Under COEP, a cross-origin iframe (e.g. archive.org/embed/...) is blocked unless that document itself sends COEP (and CORP). The <iframe credentialless> escape hatch works only in Chromium 110+; Firefox and Safari do not support it. With require-corp, no-cors cross-origin subresources (plain <script src>, <img>) need a CORP header from the CDN; whether jsDelivr sends one was not confirmed. COEP credentialless relaxes this for no-cors loads (not supported in Safari).
  => Never cross-origin-isolate a page that shows Vault (archive.org) embeds or third-party thumbnails. Isolate ONLY a dedicated page (e.g. lab/isolated.html, used just for PSP or other thread-only cores). For that page, self-host the EmulatorJS files and the threaded core, or use credentialless COEP on Chromium/Firefox.
- [verified] Only EmulatorJS's PSP (ppsspp) and DOS (dosbox_pure) cores need SharedArrayBuffer / cross-origin isolation among the four emulators. js-dos, v86, Ruffle and all other EmulatorJS cores run without it.
  => Default architecture: no COOP/COEP anywhere. Add the conditional SW header path only if PSP is in scope.
- [likely] MV3 extension pages allow only 'self', 'none' and 'wasm-unsafe-eval' in script-src and worker-src (no remote URLs, no unsafe-eval). js-dos (remote emulators.js plus a blob: Worker) and EmulatorJS (blob: core script, remote loader) therefore cannot run on extension pages as published.
  => In the extension, the Emulator Lab button should open the hosted PWA Lab URL in a normal tab rather than embedding the emulators. This also avoids bundling GPL code and the Web Store's remote-code policy.
- [likely] License implications: js-dos is GPL-2.0 (DOSBox/DOSBox-X), EmulatorJS GPL-3.0 (RetroArch/libretro, cores vary, some non-commercial), v86 BSD-2-Clause, Ruffle MIT/Apache-2.0, SeaBIOS LGPLv3. Copying them into the GitHub Pages site, the APK or the extension zip does count as distribution, and then requires license texts plus access to the corresponding source (upstream repos at the pinned tags).
  => Prefer runtime CDN loading for GPL emulators in the PWA and use an iframe/postMessage boundary between Byways code and emulator code. Keep Byways under a GPL-compatible license (MIT or GPL-3.0). Ship THIRD_PARTY_NOTICES with name, version, license, source URL. If anything is vendored into the APK, include the full license texts and source links in an in-app 'Licenses' screen.
- [likely] All four emulators need an origin with storage (IndexedDB/OPFS/localStorage). A sandboxed iframe without allow-same-origin gets an opaque origin and loses that storage.
  => Host each Lab runner as a same-origin page (lab/dos.html, lab/console.html, lab/pc.html, lab/flash.html) in an iframe with sandbox='allow-scripts allow-same-origin allow-pointer-lock' plus allow='fullscreen; gamepad; autoplay'. Do not use srcdoc or opaque-origin sandboxes.
RISKS:
- jsDelivr URLs (npm/js-dos@8.5.3, @emulatorjs/*@4.2.3, v86@0.5.473, @ruffle-rs/ruffle@0.7.1) and cdn.emulatorjs.org/4.2.3/data/ could not be fetched from this sandbox (proxy 403). Their availability, MIME type (application/wasm) and CORS/CORP headers are untested.
- EmulatorJS 4.2.3 dates from mid-2025, and 4.3.0-pre rewrites subsystems with incompatible cores. A 4.3 stable release could change the globals API, and older cores could disappear from cdn.emulatorjs.org.
- The EJS_biosUrl failure with a File or Uint8Array (assetUrl.split) and the BIOS naming problem with blob URLs come from reading the code, not from running it. They need a test before the BIOS shelf is built.
- Whether SharedArrayBuffer and service-worker-injected COOP/COEP work in the Android WebView wrapper was not verified. A native shouldInterceptRequest header injection may be needed if PSP is in scope.
- js-dos 'Mobile support (v8 - WIP)': DOS on phones may be rough. v86 has no on-screen keyboard.
- The BIOS requirements for 3DO (opera), Atari 5200, ColecoVision and Lynx were not confirmed from official docs (emulatorjs.org pages are JS-rendered).
- AudioContext and autoplay policies require a user gesture before emulator audio starts. This may conflict with 'hands-free on by default' auto-launch; it was not researched in depth here.
- Large user files: EmulatorJS and js-dos copy the entire file into memory. Multi-hundred-MB ISOs may crash mobile tabs. Only v86 streams Files of 256 MB or more lazily.
- Short commit hash only (315b2b0) for v86 0.5.473. It is unconfirmed whether jsDelivr /gh/ accepts short SHAs, so the full SHA must be looked up before pinning the BIOS URLs.
- Some libretro cores are non-commercial (snes9x, genesis_plus_gx, mame2003, likely fbneo). Any future monetisation or ads would conflict with them.
RECS:
- Default architecture: no cross-origin isolation anywhere. js-dos (DOS), EmulatorJS non-threaded cores (consoles), v86 (PC VM) and Ruffle (Flash) all run on plain GitHub Pages. Treat PSP (ppsspp) as optional v2, served from one dedicated isolated page.
- Build ONE service worker for the PWA. If isolation is ever needed, copy coi-serviceworker's header logic into it and add COOP/COEP/CORP only for navigations to lab/isolated.html and that page's subresources (use clientId). Never register coi-serviceworker.js as a second worker, and never isolate pages with archive.org embeds.
- Run each emulator in its own same-origin iframe runner page (lab/dos.html, lab/console.html, lab/pc.html, lab/flash.html). Send the File by postMessage, and destroy the iframe to stop. This contains EmulatorJS's global/singleton design and v86's window-level key listeners, and keeps a clean boundary between GPL code and Byways code.
- Keep a pinned versions manifest in the shared core: js-dos 8.5.3, @emulatorjs/emulatorjs 4.2.3 (cores 4.2.3), v86 0.5.473, @ruffle-rs/ruffle 0.7.1. Build every CDN URL from it, and always set js-dos pathPrefix (its default is v8.js-dos.com/latest).
- js-dos start: Dos(el,{url: URL.createObjectURL(file), pathPrefix:'https://cdn.jsdelivr.net/npm/js-dos@8.5.3/dist/emulators/', backend:'dosbox', fsChanges:{urlToKey: () => 'dos-'+sha256}}). Prune OPFS jsdos/caches/bundles 'blob_*' entries after each session.
- EmulatorJS start: set EJS_player='#game', EJS_core=<system>, EJS_gameUrl=<File>, EJS_gameName=<stable id>, EJS_pathtodata=<pinned data URL>, and EJS_paths for jsDelivr core files if used. Then inject loader.js. Provide user BIOS as a blob URL of an in-browser ZIP that holds the correctly named BIOS.
- v86 start: new V86({wasm_path: pinned v86.wasm, bios/vga_bios from vendored files, cdrom|hda|fda: {buffer: file}, memory_size: 128 MB default (configurable), screen:{container}, autostart:true}). Persist with save_state() into IndexedDB keyed by (disk hash, options, v86 version).
- Vendor v86 seabios.bin + vgabios.bin (LGPLv3) into the repo with notices, because they are absent from npm. Alternatively pin them via jsDelivr /gh/copy/v86@<full-sha>/bios/.
- Ruffle start: script from jsDelivr @0.7.1, then RufflePlayer.newest().createPlayer() and player.ruffle().load({data: await file.arrayBuffer(), swfFileName: file.name}).
- For offline use, have the SW cache each emulator's files on first use. For EmulatorJS that must include cores/reports/<core>.json, or core caching is disabled.
