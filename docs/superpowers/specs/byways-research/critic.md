## critic review

### Contradictions between the topic notes
- Emulator hosting: the emulators researcher recommends loading GPL emulators from jsDelivr at runtime in the PWA, so Byways does not 'convey' them. platform-shells says to vendor all third-party code with 'no CDN at runtime anywhere'. The MV3 extension (no remote code) and an offline APK need vendored copies anyway, so the GPL notice and source duties apply whichever way the PWA goes.
- Emulators in the extension: platform-shells says to vendor js-dos, EmulatorJS and v86 into the extension and add 'wasm-unsafe-eval' so they run. The emulators researcher says js-dos (blob: Worker) and EmulatorJS (blob: core script) cannot run under the MV3 extension_pages CSP, so the Lab button should open the hosted PWA Lab instead. platform-shells offers sandboxed pages as a way around this, but the emulators researcher found that opaque-origin sandboxes lose the IndexedDB, OPFS and localStorage the emulators use for saves.
- Provider client architecture: claude-browser recommends vendoring the pinned 367 KB @anthropic-ai/sdk bundle. other-providers recommends small fetch adapters and no vendor SDKs. claude-browser itself says a 5-10 KB raw-fetch adapter would work.
- Streaming: claude-browser says streaming is needed to read finds aloud as they arrive. other-providers says AI Search should default to non-streaming, because OpenAI org verification returns 400 on streaming and Groq structured outputs do not work with streaming.
- Android native HTTP bridge: claude-browser says the WebView needs no native bridge, because Anthropic CORS works from appassets.androidplatform.net. other-providers and platform-shells say Mistral and DeepSeek, which lack CORS, need a Kotlin nativeFetch bridge. platform-shells also says the bridge should allow only https URLs, yet other-providers' Android setup for Ollama and LM Studio is plain http over the LAN. An https-only bridge, and mixed-content blocking on the https appassets page (my judgment), would both block that.
- Android speech path: platform-shells says voice commands may use in-page webkitSpeechRecognition with the native recogniser as fallback. hands-free says the Android app must not depend on the WebView web API and must prefer the native bridge. hands-free also describes the bridge as 'a JS interface', while platform-shells forbids addJavascriptInterface and requires WebViewCompat.addWebMessageListener.
- WebView mic grant: hands-free cites Capacitor's request.grant(request.getResources()). platform-shells cites the Android docs warning against granting every requested resource, and says to grant only RESOURCE_AUDIO_CAPTURE, and only for the appassets origin.
- Extension mic prompt: platform-shells marks 'popups, side panels and offscreen documents cannot show the microphone prompt' as verified, but its evidence (the offscreen-user-media sample) covers offscreen documents only. hands-free marks the popup and side-panel cases unverified and says to test whether the side panel can prompt.
- Toolbar button: platform-shells and landscape make a toolbar click mean Stumble (tabs.update in the real tab, with openPanelOnActionClick off). hands-free says the toolbar Stumble button and a command shortcut act as 'push-to-talk or next'. One click cannot do both.
- Space key is assigned three ways: landscape copies Kagi's Space = next, hands-free uses K/Space to pause lean-back, and hands-free also lists Space as push-to-talk.
- Command vocabulary: landscape recommends one-word commands (next, back, save, more, read, stop). hands-free recommends distinct two-syllable phrases ('next one', 'go back', 'save it') because Android recognisers drop short single words, while also requiring command words to match the visible button labels (WCAG 2.5.3), which are mostly single words. The two sets also differ ('more' vs 'rabbit hole / more like this', 'read' vs 'read it').
- The brief's 'everything stays on the device' conflicts with the findings. Default speech recognition in Chrome, Edge, Safari and the Android browsers runs in the cloud (audio goes to Google, Microsoft or Apple). BYOK AI calls and source APIs send queries off the device. other-providers even suggests Groq for parsing voice commands. The promise must be restated as 'no Byways server; your data is stored only on your device'.
- The brief's 'hands-free ON BY DEFAULT' conflicts with the findings. On the web, speechSynthesis (likely) and probably recognition need a user activation on every page load. Cloud recognition should be opt-in. Chrome Android has no continuous mode and beeps on every restart. Extension voice needs a side panel, which sidePanel.open() can open only from a user gesture. The Prompt API model download and EmulatorJS audio also need a gesture. Only the Android app can start with no touch.
- Opening finds conflicts with keeping hands-free alive. platform-shells and landscape open frame-blocked finds in a new tab (PWA) or offer a Custom Tab (Android). hands-free says to pause listening on visibilitychange=hidden (web) and to stop in onPause (Android). Either way, voice 'next' stops working while the user is looking at the find.
- Auto-advance vs WCAG 3.2.5: the extension's Stumble model navigates the user's real tab, but hands-free says auto-advance must never open tabs or pages by itself. Lean-back in the extension would take over the user's current tab every N seconds.
- Daily Fate source: the IA researcher proposes a date-seeded offset into a live IA query (sort identifier asc, with a publicdate bound) and admits it drifts when items are removed or made dark. free-sources says offsets into live collections are not identical across users and recommends date-native content (Wikipedia feed/featured/{date}, APOD date=). The brief requires the same pick for everyone.
- Hidden-gem scoring: landscape wants a Bayesian-averaged rating with a minimum review count. The IA researcher says reviews have been hidden by default since about May 2025 and most software items have few or none, so ratings must be an optional boost, never a filter. A minimum-review gate would leave the Vault nearly empty.
- Fate: the brief says 'pure random', while landscape says random only over a curated, worksafe, surprise-worthy pool (the Wiby model). The IA researcher's Fate is random over whole collections.
- Source lists disagree. landscape names Wiby surprise, Neocities featured and random, XXIIVV and other webrings, and Marginalia random as seed sources. free-sources' ranked ship list leaves out Neocities and the webrings (nobody researched their CORS) and puts Wiby in the probe tier because its CORS is unconfirmed.
- Kagi lists in the PWA: landscape says not to assume CORS and to ship a derived seed snapshot. free-sources verified that raw.githubusercontent.com serves the lists with access-control-allow-origin: *, so they can be fetched live. Only the kagi.com feed and the /api/random path are unverified.
- CSP connect-src: claude-browser says connect-src https://api.anthropic.com plus the listed providers. other-providers says custom endpoints force 'https:' plus http://localhost:* and http://127.0.0.1:*. landscape's liveness checks on arbitrary find URLs would also need a broad connect-src. GitHub Pages cannot send headers, so the PWA's CSP can only be a meta tag.
- Gradle wrapper: platform-shells recommends setup-gradle with gradle-version 9.7.1 so no gradle-wrapper.jar is committed, but its CI recipe then runs ./gradlew assembleDebug, which needs that wrapper.
- Emulator sandboxing vs key safety: the emulators researcher recommends same-origin Lab iframes with sandbox='allow-scripts allow-same-origin'. That combination isolates nothing (my judgment), and the code inside is third-party, possibly CDN-loaded. claude-browser and other-providers require that stored API keys be protected from other script in the origin. On Android, an addWebMessageListener origin rule for appassets would also expose BywaysNative to those same-origin Lab frames.
- Licence advice: the emulators researcher says Byways may be 'MIT or GPL-3.0'. js-dos is declared 'GPL-2.0' (possibly GPL-2.0-only; nobody checked) and EmulatorJS is GPL-3.0. GPL-3.0 glue that counts as combined with GPL-2.0-only js-dos could be incompatible (my judgment). MIT glue, with each emulator in its own runner page, avoids the question.
- Firefox data_collection_permissions: platform-shells says required:['none'] is accurate because data stays on the device. In fact the extension sends search terms and queries to AI providers and source APIs, which are third parties. Whether AMO counts that as data collection is unverified (my judgment).

### Risky assumptions and fallbacks
- archive.org/embed/<id> can be framed from https://iteatsthesalt.github.io, from chrome-extension:// pages and from the https://appassets.androidplatform.net WebView origin. The X-Frame-Options and CSP frame-ancestors headers were never read, and the Vault's core play path depends on them.
  => Fallback: Detect failure with a ~15 s timeout or a user 'not working' tap, then open https://archive.org/details/<id> top-level: a new tab in the PWA, the Byways tab in the extension, an in-app top-level WebView on Android. Mark the item embed-broken locally. Probe the headers live before freezing the spec.
- advancedsearch.php and /metadata send access-control-allow-origin: *. This rests on a single community probe dated 2026-09-15, and the whole PWA Vault depends on it.
  => Fallback: In the extension and Android, use privileged fetch (host_permissions or the native bridge). For the PWA, a scheduled GitHub Actions job builds a static same-origin gems index (vault/*.json) from the same queries.
- Anthropic direct browser access keeps working, and 200 and SSE responses carry ACAO * the way the observed 401s did. No official doc for the anthropic-dangerous-direct-browser-access header was found.
  => Fallback: Make the first key validation (GET /v1/models) the live test. If a valid key fails with a TypeError, route Claude through extension or Android fetch, or through OpenRouter in the PWA.
- OpenAI, Gemini native, Groq, xAI and OpenRouter accept browser CORS calls (community evidence only), and Mistral and DeepSeek might.
  => Fallback: Probe each provider once per shell at runtime with 'Test connection' and store the result. On failure, label it 'available in the extension/Android app or via OpenRouter'. OpenRouter OAuth is the one-click fallback.
- The PWA can show arbitrary finds full screen. Many sites forbid framing, and a cross-origin page cannot read X-Frame-Options or reliably detect a blocked frame (my judgment: the load event can fire anyway).
  => Fallback: In the PWA, default to a rich preview card with an 'Open site' button. Frame only an allowlist (archive.org embeds, Byways' own pages). Treat the iframe-with-timeout path as optional and off by default.
- 'Liveness-check each find before showing it' works in the PWA. Cross-origin fetches without CORS return opaque responses, so a 404 cannot be told apart from a 200; only DNS or network failures show up (my judgment).
  => Fallback: In the PWA, check only for 'domain reachable' with a no-cors HEAD/GET. In the extension and Android, do a real status check through privileged fetch. Keep a local dead-site list fed by user 'broken' reports.
- Hands-free voice can be on by default on the web.
  => Fallback: One large 'Start' press per launch unlocks speech, the mic, the wake lock and auto-advance. On Android browsers, iOS and any cloud-only engine, default to tap-to-talk. Read-aloud, auto-advance and keyboard or headset control work without voice.
- On-device recognition (processLocally) is available enough to justify always-on listening. It is desktop Chromium 139+ and Firefox 160 only; pack size, language coverage and whether Edge honours it are unknown.
  => Fallback: When available() is not 'available' and the user declines the install() download, use push-to-talk with an explicit, vendor-named cloud opt-in. Otherwise run with no voice.
- Android devices have a usable RecognitionService. The WebView path needs a Google-provided one, and de-Googled or some OEM devices may have none.
  => Fallback: The native SpeechRecognizer bridge accepts any provider. If none exists, hide voice, keep native TTS, MediaSession headset buttons and tap controls, and say why in Settings.
- Media Session action handlers will route headset next/previous/play-pause to a page that only uses speechSynthesis. My judgment is that Chrome may require an active media element; this was not researched.
  => Fallback: Test on real devices. If handlers never fire, play a muted or very quiet audio element while lean-back is active (test first), or rely on keyboard and voice. Android uses a native MediaSession.
- The emulator CDNs (jsDelivr npm paths, cdn.emulatorjs.org/4.2.3) serve the pinned files with correct MIME types and CORS/CORP. All of them returned 403 from this sandbox.
  => Fallback: CI runs `npm pack` on the pinned versions, checks integrity, unpacks them into vendor/<pkg>@<ver>/, and serves them same-origin from Pages and from the APK. Set js-dos pathPrefix and EJS_pathtodata to those paths.
- The MV3 extension can host the Emulator Lab.
  => Fallback: The extension's Lab button opens the hosted PWA Lab in a tab. The Vault (archive.org iframes) stays in the extension.
- EmulatorJS EJS_biosUrl handles a blob URL of an in-browser ZIP correctly. This comes from reading the code, not from running it.
  => Fallback: Write a test before building the BIOS shelf. If it fails, launch BIOS-needing systems (PS1, Sega CD, Saturn, 3DO) without a BIOS where the core allows it, or leave them out of v1.
- The shared iteatsthesalt.github.io origin is acceptable for storing API keys next to same-origin, third-party emulator code and any other Pages project on that account.
  => Fallback: Recommend a custom domain for Byways. Optionally encrypt keys at rest with a user passphrase through WebCrypto (my judgment). Warn in Settings, and tell users to create spend-limited keys.
- The Kagi random endpoint lives at https://kagi.com/smallweb/api/random. The path is inferred, and live CORS is unverified.
  => Fallback: Use the verified raw.githubusercontent.com lists (smallweb.txt, smallyt.txt, smallcomic.txt), cached weekly in IndexedDB with junk lines filtered out.
- Daily Fate computed on each client gives the same pick for everyone. It depends on a live numFound and on identical hash code in every app version and shell.
  => Fallback: A GitHub Actions job writes a static daily.json at 00:00 UTC. Clients use it and fall back to a spec-fixed seed algorithm over date-native sources (Wikipedia feed/featured/{date}, APOD date=).
- The Android toolchain resolves: AGP 9.3.2, androidx.webkit 1.18.0, Gradle 9.7.1. Google Maven was unreachable, and several versions rest on search snippets.
  => Fallback: The first green CI build is the check. Fall back to androidx.webkit 1.17.x, pin runs-on to ubuntu-24.04 and pin JDK 21 with setup-java.
- Friends can update the APK in place.
  => Fallback: The user creates one release keystore and stores KEYSTORE_BASE64, KEYSTORE_PASSWORD, KEY_ALIAS and KEY_PASSWORD as repository secrets. Without them, ship debug APKs with an 'uninstall before update' warning.
- web_search plus output_config.format, and the claude-browser recommendation to send betas ['server-side-fallback-2026-07-01'] with fallbacks:'default'. No fact in the findings supports either.
  => Fallback: Use the strict report_finds client tool. Send no beta or fallbacks fields until they are verified against the docs.
- AI-team cost stays near the $0.27-0.64 estimate, which rests on an assumed 5-20K tokens per search.
  => Fallback: Make AI-team mode opt-in. Enforce a hard per-run dollar cap computed from each provider's reported usage, abort the remaining members when it is hit, set a daily search cap per provider, and never run AI in lean-back unless the user opts in.
- Lean-back auto-advance works when the find opens outside the Byways surface (new tab, Custom Tab, the user's own tab).
  => Fallback: Run lean-back only inside a Byways-owned surface: the PWA card view, a dedicated Byways tab in the extension, or a second in-app WebView on Android. Pause and announce when the user opens a find elsewhere.
- Large user files load in the Lab on phones. EmulatorJS and js-dos read the whole file into memory.
  => Fallback: Warn above ~500 MB on mobile. Route large disk images to v86, which streams Files of 256 MB or more lazily.

### Gaps
- Data across the three versions: the PWA, extension and Android app each have their own storage origin, so collections, the seen-set, the taste profile and keys are not shared even on one device. The spec needs an export/import format (versioned JSON), a keys-excluded rule, and a way to move data between them (file, link or QR).
- Share-link format: payload schema, versioning, compression and maximum length. Also what happens when a link is opened in each shell: Android intent filters, and whether App Links can be verified at all for a project page whose host root /.well-known/assetlinks.json lives in a different repo (my judgment), plus extension interception.
- The exact deterministic seed for Daily Fate: hash and PRNG algorithm, UTC vs local-date rollover, and the ordered candidate list. It must be identical across shells and app versions.
- The Tuned-mode algorithm: taste-profile schema, how thumbs, 'less of this topic' and 'never this site' change the weights, cold start, and the Familiar <-> Strange blend maths.
- Offline similarity for Rabbit Hole: tags, TF-IDF or in-browser embeddings, and the size budget. Also per-source 'more like this' for IA items, which nobody researched.
- Card imagery for finds with no image (Kagi lists, Marginalia, HN, GitHub). The PWA cannot fetch og:image cross-origin, and screenshot or favicon services leak browsing to third parties.
- What exactly is read aloud for each source type. Reader mode needs the page content, which the PWA cannot fetch cross-origin; the extension and Android can.
- Content safety and worksafe policy per source (Commons random images, IA feature_films, Wikipedia random, Kagi lists), especially if friends include minors. Which mature flags exist and get applied.
- Video finds (the Kagi smallyt list, IA films): how YouTube and other video embeds play in each shell, including WebView embed restrictions. Not researched.
- The offline scope in each shell: what works offline, the service-worker cache strategy and budget, and what happens on Android, which skips the service worker.
- The v1 EmulatorJS system and core list, and the total size budget for the Pages site (1 GB limit), the APK, and on-demand downloads. On Android, cores downloaded after install cannot be served by an assets-only WebViewAssetLoader (my judgment).
- v86 content: which OS or disk images users bring, whether to ship any freely licensed OS image, and a default memory size for phones.
- Touch and keyboard input for IA embeds on phones (no virtual keyboard known), and the design of v86's app-drawn soft keyboard.
- AI-team orchestration: role prompts, how a curator without search receives candidates, the merge and dedupe rules, usage and cost parsing for each provider's response format, cross-provider budget enforcement, partial failures, and handling prompt injection from search results.
- Key-management UX for every key the user will enter. On device: AI providers, api.data.gov, Europeana, Openverse client credentials, Marginalia, a GitHub PAT, a Picovoice AccessKey. As repo secrets: the Android keystore, AMO keys, an optional Pages PAT. Also validation, at-rest protection, the Android EncryptedSharedPreferences option, and OpenRouter PKCE callbacks in the extension (identity permission) and on Android.
- Extension distribution: Chrome Web Store vs load-unpacked for friends, the privacy policy required by the stores, an Edge Add-ons listing, AMO unlisted signing, and store review of an extension that embeds remote sites and calls many AI providers.
- The licence for Byways itself, a THIRD_PARTY_NOTICES plan, and the attribution text for Kagi (MIT), Wikipedia (CC BY-SA) and IA.
- What is already in iteatsthesalt/Game-Dev-Resources and whether Pages is already on for it. Nobody checked whether Byways replaces existing content, lives in a subfolder, or collides with a branch-based Pages site.
- A testing plan: CI tests (e.g. a headless browser), a live CORS and header probe script to run once the network allows, and a real-device matrix for every item marked likely or unverified.
- iOS: whether Safari and iPhone friends are in scope at all. Only BCD rows were gathered (webkit-prefixed, Siri-backed recognition; wake lock in home-screen apps only from 18.4).
- Extension details: whether activeTab is granted when Rabbit Hole starts from a side-panel button, whether the side panel is per-tab or global, and how the panel learns the current find after tabs.update.
- The origin of the GeoCities-era seed URL list, its licence, and its size.
- Terms of use nobody read: IA Terms (not reachable), itch.io feed scraping by a scheduled Action, the Kagi feed and API terms, Marginalia key terms, the Picovoice licence.
- The Android minSdk decision: minSdk 24 (platform-shells) vs API 33 as the continuous hands-free baseline (hands-free), and what users on 24-32 get.
- UI and voice language support. Kagi's lists are English-only, so non-English recognition and voices and the command grammar are unspecified.
- A plan for storage eviction and quotas: navigator.storage.persist() in each shell, and the OPFS cache pruning for js-dos.
- Back and history navigation across the SPA, the Stumble Back history (~50) and Android predictive back, and whether that history persists across sessions.

### Suggested spec decisions
- Restate the promise: 'No Byways server. Your keys, collections and history are stored only on this device. Network calls go only to the sources and AI providers you turn on.'
- Hands-free default = read-aloud + lean-back auto-advance + voice. On the web and in the extension it is armed by one 'Start' press per launch. The Android app (API 33+) may start listening with no touch after a first-run consent screen.
- PWA voice: on desktop Chrome/Edge 139+ and Firefox 160+, use SpeechRecognition with processLocally (install() from a click), quality 'command' and phrases bias. Cloud recognition runs only after an opt-in that names the vendor. Android and iOS browsers default to tap-to-talk. Read-aloud uses speechSynthesis, one sentence per utterance, local voices first.
- Extension voice: only in the Chrome/Edge side panel, the Firefox sidebar or a Byways tab, after a one-time permission.html mic grant. Use chrome.tts on Chrome and speechSynthesis elsewhere. Never listen while the panel is closed.
- Android voice: native SpeechRecognizer (on-device recogniser, EXTRA_SEGMENTED_SESSION + EXTRA_AUDIO_SOURCE on 33+, restart loop or tap-to-talk below that), native TextToSpeech and a native MediaSession. Bridge through addWebMessageListener for the appassets origin only, accept main-frame messages only (judgment), and never use addJavascriptInterface.
- Commands are the visible single-word button labels, plus accepted two-word synonyms ('next one', 'go back'). Match them locally against the whole final utterance. Never send command parsing to an LLM. Only 'search for <words>' goes to AI.
- Key map (judgment): Space = Stumble/next, K = pause/resume lean-back, hold V or a headset button = push-to-talk, Esc = stop reading (inactive while a Lab iframe has focus). Single-key shortcuts can be turned off.
- Showing finds: the PWA shows a preview card with 'Open' and frames only archive.org embeds and its own pages. A manual toolbar Stumble in the extension navigates the current tab, while extension lean-back runs in a dedicated Byways tab. Android opens finds in a second in-app WebView, never a Custom Tab, so voice keeps working.
- AI providers callable directly from the PWA, each after a runtime 'Test connection' probe: Anthropic (CORS verified), OpenAI (POST /v1/responses with web_search), Gemini native (google_search; never the OpenAI-compatible endpoint), OpenRouter (openrouter:web_search plus a 'Connect OpenRouter' PKCE button), Groq (groq/compound-mini), xAI (/v1/responses with web_search). Add local Ollama and LM Studio with setup text, and Chrome built-in Nano on desktop only (no search; ranking and blurbs).
- AI providers only in the extension and Android, or through OpenRouter: Mistral (/v1/conversations with web_search), DeepSeek (POST /responses with deepseek-v4-pro and web_search; prefer Android native fetch because the extension's Origin header may be rejected), and the Ollama web_search API.
- Use one fetch-adapter layer for every provider, Anthropic included. The Anthropic adapter copies the SDK's headers, including anthropic-dangerous-direct-browser-access: true and a pinned anthropic-version, and sends no temperature, top_p or top_k. The SDK bundle is not shipped (judgment).
- AI Search is non-streaming in v1. Finds are read aloud only after report_finds has been validated and every URL checked against the web_search results.
- Claude AI Search: web_search_20260209 with max_uses 3; allowed_callers ['direct'] when capabilities.code_execution is unsupported; a strict report_finds tool; a pause_turn loop that passes the container id back, capped at 5; error mapping for 401, 'web search not enabled' and 429.
- Cost guards: the default AI is a single model (suggest Sonnet 5.5 or Haiku 5.5, or the cheapest key the user entered). AI-team mode is opt-in with a hard per-run cap (e.g. $0.50) and 50 searches per provider per day. AI never runs during lean-back unless the user opts in.
- Transport interface: browser fetch (PWA), extension-page fetch with host_permissions (extension), nativeFetch over the bridge (Android). The Android bridge allows https plus user-approved LAN http hosts for local models, through network_security_config (judgment).
- Internet Archive runtime: advancedsearch.php only, plus /metadata/<id>/metadata to require metadata.emulator before showing Play. One request queue at 1 per second and 2 at a time, honouring Retry-After, with an IndexedDB cache (24 h for search, 7 d for metadata).
- Vault collections: hard-code the verified softwarelibrary_c64_games, softwarelibrary_apple_games, zx_spectrum_library_games and softwarelibrary_msdos_shareware. Add the likely softwarelibrary_msdos_games, softwarelibrary_win3_games, softwarelibrary_amiga, softwarelibrary_mac, consolelivingroom, atari_2600_library, internetarcade, softwarelibrary_flash, softwarelibrary_flash_showcase, softwarelibrary_palm and malwaremuseum, each validated at first run. Drop atari_7800_library, handheldhistory, softwarelibrary_flash_games, softwarelibrary_amiga_games and softwarelibrary_win3_shareware.
- Non-game IA Stumble sources, each validated at runtime: prelinger, feature_films, georgeblood, 78rpm, oldtimeradio, librivoxaudio, etree, computermagazines. Old-web cards come from a static GeoCities seed list resolved through wayback/available with timestamp=2009.
- Gem score: downloads:[20 TO 3000], curated-collection membership and age. Ratings only boost the score and never gate it. Every gem card shows why it counts as a gem.
- Vault play: mount the archive.org/embed iframe only after Play, with allow='fullscreen; autoplay; gamepad'. After 15 s without loading, offer 'Open on archive.org' and mark the item embed-broken locally. Never fetch IA files into the Lab.
- Daily Fate: a GitHub Actions job writes a static daily.json at 00:00 UTC that picks across the verified IA collections, Wikipedia's featured feed and APOD. The client fallback uses a spec-fixed hash and PRNG (e.g. FNV-1a + mulberry32; judgment) seeded with 'byways-daily-' + the UTC date.
- Emulators, pinned: js-dos 8.5.3 (dosbox backend; DOSBox-X opt-in), EmulatorJS 4.2.3 non-threaded cores only (v1: nes, snes, gb, gba, segaMD, segaMS, segaGG, atari2600, psx with an optional user BIOS), v86 0.5.473 with vendored seabios.bin and vgabios.bin (LGPLv3), and Ruffle 0.7.1 for the user's own SWFs. No PSP or dosbox_pure in v1, and no COOP/COEP anywhere.
- Emulator hosting: CI vendors the pinned npm tarballs into vendor/<pkg>@<ver>/, served same-origin from Pages and bundled into the APK. The extension Lab opens the hosted PWA Lab in a tab. Each emulator runs in its own runner page (lab/dos.html, lab/console.html, lab/pc.html, lab/flash.html) and receives the File by postMessage.
- Licensing (judgment): Byways glue is MIT. Each emulator stays a separate program in its own runner page. Ship THIRD_PARTY_NOTICES and an in-app Licenses screen with version, licence and upstream source link for each component, and keep the Lab ad-free.
- Free sources callable directly in v1 (CORS verified): Wikipedia (REST, plus Action API with origin=*), Wikimedia Commons, iNaturalist, Open Library .json, Marginalia (API-Key: public), GitHub topic search, NASA APOD, Art Institute of Chicago (with an image onerror fallback), and the Kagi lists through raw.githubusercontent.com. HN Algolia (CORS likely) also ships, inside the runtime probe.
- Key-unlocked sources: Europeana, Openverse (registered client credentials) and Smithsonian, which shares the api.data.gov key with NASA. Probe tier (shown only if the runtime check passes): Met v1.1, Cleveland, NASA Images, Library of Congress, Wiby, Kagi /api/random. Privileged-only: itch.io .xml feeds in the extension and Android, or a GitHub Actions snapshot to /data/itch.json.
- Each source gets a token bucket (e.g. iNat and Open Library 1/s, AIC 60/min, GitHub search 10/min, Wikimedia about 10/min), an IndexedDB cache, at most 3 finds prefetched ahead and a permanent seen-set. Sponsored finds and engagement ranking are never allowed.
- Render every third-party string with textContent, using plain-text fields (extract, not extract_html). No innerHTML anywhere. A per-page meta CSP with connect-src 'https:' plus localhost, and blob: allowed in script-src and worker-src only on the Lab runner pages.
- Keys the user enters stay in device storage per shell and are never written to exports, share links or logs. Repo secrets (Android keystore, AMO_API_KEY/AMO_API_SECRET, an optional Pages PAT) live in GitHub Settings and are never committed. Recommend a custom domain because github.io is a shared origin.
- Android build: AGP 9.3.2, Gradle 9.7.1, built-in Kotlin, compileSdk 37, targetSdk 36, minSdk 24 (continuous hands-free from 33), androidx.webkit 1.18.0, JDK 21, runs-on ubuntu-24.04. Either commit the wrapper and run ./gradlew, or run `gradle` through setup-gradle with gradle-version 9.7.1; pick one.
- Extension: one template generates the Chrome/Edge manifest (side_panel) and the Firefox manifest (sidebar_action, gecko id, strict_min_version 140.0). CSP is "script-src 'self' 'wasm-unsafe-eval'; object-src 'self';". host_permissions cover archive.org plus the listed providers and sources; optional_host_permissions cover user-supplied endpoints.
