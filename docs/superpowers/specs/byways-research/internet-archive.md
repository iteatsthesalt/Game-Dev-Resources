## internet-archive
- [verified] advancedsearch.php request format: GET https://archive.org/advancedsearch.php?q=<lucene query>&fl[]=<field>&fl[]=...&sort[]=<field> <asc|desc>&rows=<n>&page=<1-based>&output=json. The response JSON is response.numFound plus response.docs[]. IA's official Python client builds the request exactly this way.
  => Build one small IA search helper in the shared core that emits fl[]/sort[]/rows/page/output=json and parses response.docs. Ask only for the fields the card needs.
- [likely] rows=0 returns only the count (numFound). rows of 1 or more works, and no minimum applies.
  => For Fate and Daily Fate, make one cheap rows=0 call to learn N, then a rows=1 (or rows=50) call at a computed offset.
- [likely] advancedsearch.php refuses to page beyond 10,000 results. The error text is '[DEEP_PAGING] Requested results would exceed the deep paging limit for this service'.
  => Random offsets must stay below min(numFound, 10000). For bigger pools, first narrow the query with a random facet (a year range, a first letter, a sub-collection), then pick a random offset inside that slice.
- [likely] No random sort option is documented for advancedsearch.php or the scrape API.
  => Generate randomness on the client: pick a random collection, then a random slice, then a random offset below 10000. Never rely on a server-side random sort.
- [likely] Sortable fields include downloads, week, month, title (titleSorter), creator, publicdate, addeddate, updatedate, item_size, files_count, num_reviews, num_favorites, and identifier. Sorting on identifier gives stable paging.
  => Daily Fate should sort by identifier asc so every user's offset lands on the same item. The hidden-gem feed can sort by downloads asc.
- [likely] Useful fl[] field names: identifier, title, creator, date, year, description, subject, collection, mediatype, downloads, week, month, avg_rating, num_reviews, publicdate, addeddate, item_size. downloads, avg_rating and similar counts come from the search index and are absent from the /metadata record.
  => Score gems from the search response, not from /metadata. Cache those scores locally (IndexedDB) by identifier.
- [likely] Ratings are probably sparse or stale. Archive.org has hidden reviews by default since about May 2025, and most software items have few reviews or none.
  => Make avg_rating and num_reviews optional boosts in the gem score, not hard filters. The main signals should be low downloads, membership in a curated collection (for example a *_showcase collection) and the item's age.
- [likely] Lucene range syntax field:[low TO high] works in q, for example downloads:[50 TO 3000].
  => Express 'hidden gem' as q=collection:(X) AND downloads:[20 TO 3000], then re-rank on the client. Check numFound before narrowing further.
- [verified] The scrape API lives at https://archive.org/services/search/v1/scrape and takes q, fields (comma-separated), sorts (comma-separated), count, cursor and total_only. Responses carry items, count, total and cursor; the client loops until no cursor comes back. The official client defaults count to 10000.
  => Scraping is only needed for a bulk crawl, such as building a static index in GitHub Actions. The runtime Stumble flow needs no scrape calls.
- [likely] The scrape count has a minimum of 100; smaller values return 400 RangeException. If identifier is one of the sorts, it must come last. Unknown parameters such as _cb are rejected.
  => Never use scrape for single-item random picks. Never add cache-busting params to it.
- [likely] The scrape API's response cache can return a different query's results: the cache key omits q, and field filters such as emulator:(genesis) appear to be ignored.
  => Use advancedsearch.php for all Byways runtime queries. If scrape is ever used, check every returned item against the query on the client.
- [verified] IA's own web front end calls an internal endpoint, /services/search/beta/page_production. Its source notes that credentialed requests are allowed only from archive.org origins because of CORS.
  => Don't build on the beta endpoint, which can change without notice. Always fetch with credentials:'omit' (the default for cross-origin).
- [verified] The read APIs (search and metadata) need no API key or login. The official client attaches auth only when keys are configured.
  => The Vault and the other IA sources need no key-entry UI. The user's offer to enter keys applies to the AI providers, not to IA.
- [likely] CORS: advancedsearch.php, the scrape API and archive.org/metadata/<id> send Access-Control-Allow-Origin: * and answer OPTIONS preflights, so a page on another origin can fetch them.
  => The PWA (GitHub Pages) can call these directly with plain GET fetches, no proxy, no credentials and no custom headers. The extension should still list https://archive.org/* in host_permissions in case CORS changes.
- [likely] CORS: archive.org/services/img/<id> returns 200 image/jpeg with no CORS headers. archive.org/download/<id>/<file> also sends no CORS headers. iiif.archive.org reflects Origin.
  => Show thumbnails with <img src> only, never with fetch() or canvas pixel reads. A service worker can cache them only as opaque responses, which carry a quota padding cost. The page cannot fetch game binaries cross-origin, which fits the Vault playing games through the embed rather than downloading them.
- [likely] Wayback availability API: GET https://archive.org/wayback/available?url=<url>[&timestamp=YYYYMMDDhhmmss][&callback=] returns {archived_snapshots:{closest:{available,url,timestamp,status}}}, or {archived_snapshots:{}} when no snapshot exists.
  => For 'old web' Stumble cards, always pass a timestamp (for example 1999 for the GeoCities era) and treat an empty archived_snapshots as a miss, then pick another URL.
- [likely] CORS on the availability API is ACAO: * together with Access-Control-Allow-Credentials: true. The Wayback CDX API (web.archive.org/cdx) sends no CORS headers.
  => Call wayback/available with a plain anonymous fetch and never credentials:'include'. Don't plan any browser-side CDX enumeration; old-web discovery needs seed URL lists shipped with the app.
- [likely] In-browser playability is driven by item metadata. mediatype=software plus emulator and emulator_ext (and usually emulator_start) mark an item as playable. DOS items use emulator=dosbox and emulator_ext=zip; Flash items use emulator=ruffle-swf and emulator_ext=swf.
  => Before showing a Play button, fetch /metadata/<id> and require metadata.emulator. Use the emulator value to label the platform and pick control hints.
- [unverified] emulator appears to be a searchable field (the unofficial wiki links archive.org/search?query=emulator:(dosbox)). Whether advancedsearch returns it through fl[] is unconfirmed.
  => Don't depend on emulator in search. Restrict candidates to known emulation collections, then confirm each item through /metadata.
- [likely] Some items are stream-only: their metadata.collection includes stream_only, they play only in IA's own in-browser player, and they can't be downloaded. In Console Living Room, 6,816 of 24,746 items are stream_only.
  => The Vault's embed-only approach handles stream_only items naturally. Never offer 'download to the Emulator Lab' for IA items, which also avoids copyright problems; the Lab stays for the user's own files.
- [likely] https://archive.org/embed/<identifier> exists for software items and serves IA's emulator page; for example archive.org/embed/msdos_Scorched_Earth_1991 is indexed. Third-party sites load IA emulation in iframes, and IA added 'share this' embeds for emulations.
  => The Vault plays games with <iframe src="https://archive.org/embed/ID" allow="fullscreen; autoplay; gamepad" allowfullscreen>. Always show an 'Open on archive.org' fallback link beside it.
- [unverified] X-Frame-Options and CSP frame-ancestors on /embed/ were not confirmed. Some embeds fail to start even though the details page works, and IA's software curator says the embed 'either works for you or it doesn't'.
  => Detect failure: if the iframe hasn't loaded within about 15 seconds, or the user taps 'not working', offer the archive.org/details link and mark the item locally as embed-broken so Fate skips it next time. Test headers once the network allows archive.org.
- [verified] Under COEP require-corp (cross-origin isolation), every cross-origin iframe must itself send COEP, or it is blocked. iframe credentialless lifts that rule, but only in Chromium 110 and later.
  => If the Emulator Lab needs SharedArrayBuffer (COOP/COEP, for example through coi-serviceworker on GitHub Pages), isolate only the Lab route or page. Never isolate the Vault or feed pages, or the archive.org iframes and services/img thumbnails will break, in Firefox especially.
- [verified] Item identifiers and URLs follow fixed patterns, for example msdos_Whizz_1994. Files are at https://archive.org/download/<id>/<file>, item pages at /details/<id> and thumbnails at /services/img/<id>.
  => Store only the identifier in collections and share links, and derive every URL from it. That keeps share-by-link payloads tiny.
- [likely] Metadata API: GET https://archive.org/metadata/<id> returns metadata{}, files[], server, dir and related fields. Sub-paths such as /metadata/<id>/metadata and /files?start=&count= exist. There is no batch form, and an unknown item returns an empty result.
  => Fetch /metadata/<id>/metadata (a smaller payload) to confirm playability. Normalise collection to an array, treat {} or an empty result as not found, and limit concurrency to 2-3 requests.
- [verified] Playable software collection identifiers confirmed from live archive.org/details pages in search results: softwarelibrary_c64 and softwarelibrary_c64_games ('Software Library: C64: Games'); softwarelibrary_apple and softwarelibrary_apple_games ('The Apple II Library: Games'); softwarelibrary_zx_spectrum and zx_spectrum_library_games ('ZX Spectrum Library: Games'); softwarelibrary_msdos_shareware ('Software Library: MS-DOS Shareware').
  => Hard-code these in the Vault source list.
- [likely] Strongly indicated but not seen as live pages: softwarelibrary_msdos_games (MS-DOS Games), softwarelibrary_msdos (MS-DOS general), softwarelibrary (parent), softwarelibrary_win3_games (Windows 3.x Games), softwarelibrary_amiga, softwarelibrary_mac (Macintosh), consolelivingroom, atari_2600_library, internetarcade (Internet Arcade, MAME), softwarelibrary_flash and softwarelibrary_flash_showcase (Flash via Ruffle), softwarelibrary_palm, malwaremuseum.
  => Include all of these, but check each at first run (a /metadata/<id> call returning mediatype 'collection') and drop any that fail, so a wrong identifier can't break the Vault.
- [unverified] Not confirmed: atari_7800_library, softwarelibrary_flash_games, handheldhistory (Handheld History), softwarelibrary_win3_shareware, softwarelibrary_amiga_games.
  => Find sub-collections at runtime instead (q=collection:(consolelivingroom) AND mediatype:collection, or collection:(softwarelibrary) AND mediatype:collection), and filter Atari 7800 by the emulator value inside consolelivingroom. Never fall back to user-uploaded ROM-set items.
- [likely] Other discovery collections: prelinger (Prelinger Archives ephemeral films, reuse per each item's CC license), georgeblood and 78rpm (Great 78 Project), oldtimeradio, computermagazines (Computer Magazine Archives), librivoxaudio, etree (Live Music Archive), feature_films.
  => Add these as non-game Stumble sources: video and audio play through the same archive.org/embed/<id> iframe, magazines open the BookReader embed. Validate them at runtime the same way as the software collections.
- [likely] GeoCities-era sites have no single archive.org/details collection. The Archive Team dump (2009-archiveteam-geocities-part1..8, about 79 GB per part) is raw data; IA presents GeoCities through the Wayback Machine (archive.org/web/geocities.php) and through GifCities (gifcities.org, rebuilt 2025), which has no documented public API.
  => Ship a static seed list of GeoCities-era URLs in the app, resolve each through wayback/available with timestamp=2009, and open the Wayback URL. Link out to GifCities rather than integrating it.
- [likely] No numeric rate limits are published. IA throttles heavy automated traffic with 429, and in September 2026 it added stronger Wayback protections that have also blocked some real users. IA's official client retries 429/500-504 with backoff, honouring Retry-After.
  => Put one IA request queue in the core: at most 1 request per second and 2 at a time, exponential backoff that honours Retry-After on 429/503, and a pause on IA calls after two 429s in a row. Prefetch at most 1-3 finds ahead during auto-advance.
- [likely] IA asks automated clients to send a descriptive User-Agent, but browsers don't let page scripts set User-Agent reliably, and custom headers trigger preflights.
  => In the PWA, send only simple GETs with no custom headers. Keep request volume low so a browser User-Agent isn't a problem. A GitHub Actions index builder, if added, must set a descriptive User-Agent that contains no personal data.
- [unverified] IA's Terms of Use describe access as for scholarship and research. No IA terms specific to embedding or API etiquette were found.
  => Keep Byways personal and non-commercial: link every Vault card to its archive.org/details page, show IA attribution, never rehost IA files, and re-read the terms page once archive.org is reachable.
- [likely] archive.org/services/collection-rss.php?collection=<id> serves an RSS feed of a collection's newest additions.
  => Optional 'fresh arrivals' source. Its CORS is unknown, so prefer advancedsearch with sort[]=publicdate desc, which gives the same data with known CORS.
RISKS:
- archive.org, help.archive.org, blog.archive.org, web.archive.org and the docs mirrors could not be reached from this machine (DNS blocked), so no response header was read directly. All CORS and frame-header findings rest on a community probe dated 2026-09-15 plus indirect evidence. Probe them live before the spec is final: curl -sI -H 'Origin: https://iteatsthesalt.github.io' on advancedsearch, metadata, services/img, wayback/available and embed/<id>, and look for x-frame-options and content-security-policy.
- Whether archive.org/embed/<software id> sends X-Frame-Options or CSP frame-ancestors is unconfirmed. If IA ever restricts framing, the Vault's core play path breaks and only link-out remains.
- Ratings (avg_rating, num_reviews) may be sparse or stale now that reviews are hidden by default, which weakens the 'well-rated' half of the hidden-gem rule.
- The scrape API's cache appears to ignore q, so its results can belong to another query. Any use of scrape is risky.
- Deep paging is capped at 10,000 results, so 'pure random' over large collections (C64 about 98k, MS-DOS about 23k) needs slicing. True uniform randomness isn't achievable with simple calls.
- Daily Fate determinism can drift within a day if items are added, removed or made dark. A publicdate upper bound limits drift from additions but not from removals.
- Several collection identifiers (atari_7800_library, handheldhistory, softwarelibrary_flash_games, softwarelibrary_amiga_games, softwarelibrary_win3_shareware) are unverified, and some likely ones were seen only in snapshots or press.
- Copyright: many emulated titles are still under copyright (PCWorld notes this for Win3.x). Embedding IA's own player is the low-risk path, while downloading the files into the Emulator Lab would not be.
- IA has had outages (the October 2024 attacks) and rising bot defences (September 2026). The app needs graceful offline and empty states when IA is down or returns 429.
- Embedded emulators may need keyboard focus, gamepad, fullscreen and audio permissions inside the iframe. The Android WebView needs a WebChromeClient that handles fullscreen. Neither was tested here.
- The wayback/available API sometimes returns empty for URLs that are archived (anecdotal reports), and the CDX fallback has no CORS.
RECS:
- Use advancedsearch.php as the only IA search endpoint at runtime. Avoid services/search/v1/scrape because of the cache-key bug, and avoid services/search/beta/page_production because it is internal. Use /metadata/<id>/metadata only to confirm a single item.
- Put one IA request queue in the shared core: plain anonymous GETs with no custom headers and no credentials, at most 1 request per second and 2 at a time, exponential backoff that honours Retry-After on 429/503, a circuit-breaker pause after two 429s in a row, and an IndexedDB cache of search slices and metadata (24h for search, 7d for metadata).
- Vault source list: hard-code the verified identifiers (softwarelibrary_c64_games, softwarelibrary_apple_games, zx_spectrum_library_games, softwarelibrary_msdos_shareware and their parents) and the likely ones (softwarelibrary_msdos_games, softwarelibrary_msdos, softwarelibrary_win3_games, softwarelibrary_amiga, softwarelibrary_mac, consolelivingroom, atari_2600_library, internetarcade, softwarelibrary_flash, softwarelibrary_flash_showcase, softwarelibrary_palm, malwaremuseum). Check each at first run with /metadata/<id> (mediatype == collection) and drop failures. Find further sub-collections with q=collection:(<parent>) AND mediatype:collection.
- Hidden-gem query: q=collection:(<id>) AND mediatype:software AND downloads:[20 TO 3000] with fl[]=identifier,title,year,creator,downloads,avg_rating,num_reviews,subject,description, sort[]=downloads asc and rows=100 at a random page. Re-rank on the client by low downloads, any rating of 4 or more with at least 2 reviews, curated-collection membership and year. Treat ratings as an optional boost.
- Fate (pure random): pick a collection, run one rows=0 call to get N, compute a random offset below min(N, 10000) (if N > 10000, first narrow by a random year range or title letter), fetch rows=1&page=offset+1, then confirm playability through /metadata (metadata.emulator present). Retry with a new pick up to 3 times before showing a friendly miss.
- Daily Fate (same for everyone): seed = hash('byways-daily-' + UTC date). Choose the collection from a fixed ordered list, query with sort[]=identifier asc and publicdate:[* TO <UTC midnight of that date>] (so new uploads don't shift the index), take offset = seed mod min(N, 10000), and fetch that one item. Optionally use a GitHub Action that writes daily.json to GitHub Pages; that is a static file, not a server.
- Play only through IA's own player: <iframe src='https://archive.org/embed/<id>' allow='fullscreen; autoplay; gamepad' allowfullscreen loading='lazy'>, mounted only after the user taps Play (to save IA load and battery in lean-back mode). Always show 'Open on archive.org' (/details/<id>). After a load timeout or a user report, mark the item embed-broken locally and skip it in Fate.
- Never fetch IA game files into the Emulator Lab. Keep the Lab for the user's own files, which sidesteps both the missing CORS on /download/ and copyright exposure.
- Keep cross-origin isolation (COOP/COEP) confined to the Emulator Lab route or page. Feed and Vault pages must not be isolated, or the archive.org iframes and services/img thumbnails will be blocked (iframe credentialless is Chromium-only).
- Thumbnails: render with <img src='https://archive.org/services/img/<id>' loading='lazy'> and never with fetch or canvas. If a service worker caches them, cache opaque responses with a small cap, or skip caching them.
- Extension: add host_permissions 'https://archive.org/*' and 'https://*.archive.org/*' so background fetches survive any CORS change. Android WebView: enable JavaScript and DOM storage, and add a WebChromeClient that handles fullscreen (onShowCustomView) for embedded emulators.
- Non-game Stumble sources: prelinger, feature_films, georgeblood, 78rpm, oldtimeradio, librivoxaudio, etree and computermagazines, all played or read through archive.org/embed/<id>. Old-web cards: ship a static seed list of GeoCities-era URLs and resolve them through wayback/available?url=...&timestamp=2009 with an anonymous fetch. Don't use CDX from the browser.
- Show IA attribution and a link on every IA card. Keep usage personal and low-volume. Before release, re-check IA's Terms of Use and the embed response headers with a live probe, since archive.org was unreachable from this research machine.
