## landscape
- [verified] Kagi Small Web ships an open-source Manifest V3 extension that is the closest existing match to the Byways extension. It has a toolbar icon that opens a side panel, a Discover button for a random post, modes (Blogs, Liked, Videos, Code, Comics, Saved), reader mode, a dyslexia-friendly font, text-to-speech, save for later, like, per-mode history and keyboard shortcuts (Space = next, R = reader, S = save, T = TTS, D = dyslexia font). Its README says all data stays in local browser storage, with no tracking or analytics.
  => Treat this as the baseline Byways must beat, not just match. Copy the Space = next keyboard model and the local-only privacy promise. Set Byways apart with what it lacks: a no-repeat memory across sessions, voice control, a games Vault, AI search, collections shared by link, and Daily Fate.
- [verified] The Kagi extension does not show posts in an iframe. It navigates the user's active tab to the post (tabs.update), and it sets the Referer header with a short-lived declarativeNetRequest dynamic rule that it removes after 30 seconds.
  => The Byways extension should work like the old StumbleUpon toolbar: the toolbar Stumble button loads the find in the real tab, which avoids frame-blocking entirely. Keep the Byways UI in a popup or side panel. Iframing is only for the PWA.
- [verified] The Kagi Small Web website only shows a post if the blog has a post less than 7 days old and the site can appear in an iframe. Domains that refuse framing (Tumblr sends X-Frame-Options: deny) get an interstitial page, because a framed page would render blank.
  => The PWA's full-screen Stumble cannot frame many sites. The spec needs a known-unframeable domain list, a load/blank-frame timeout, and a rich preview card with an 'Open site' button instead of a blank screen. In the Android app, load the find as a top-level WebView page.
- [verified] Kagi's protection against repeats is weak. A cookie holds hashes of only the last 100 URLs seen (8-character md5) and expires after 1 day (max_age 86400). When everything has been seen, it falls back to plain random.choice.
  => Make 'never show me the same thing twice' a core promise. Keep a permanent seen-set of normalized URLs in IndexedDB that never expires by default. Add a cooldown so the same domain does not come back within N stumbles. Tell the user when a pool is used up instead of quietly repeating.
- [verified] Kagi picks the next post with an explicit weighted mix. It excludes the current URL and seen URLs. When the user is browsing all topics, there is a 60% chance the next post stays in the current post's category. In blog mode there is a 7% chance the next post comes from the community-liked pool.
  => Build Tuned mode as a simple, visible blend instead of an opaque ranker: about 60% momentum (same topic), a small slice re-injected from the user's own likes, and a fixed wildcard share. Let the user adjust it with a 'Familiar <-> Strange' control, and show which branch picked each find.
- [verified] Kagi's 'Show similar' finds the most similar unseen post by cosine similarity over precomputed embeddings, and it excludes the current post and posts already seen.
  => This is direct precedent for Rabbit Hole. Rabbit Hole must exclude seen items. It can use local similarity (shared tags or TF-IDF over titles and descriptions) offline, and AI suggestions when a key is set. Show a breadcrumb trail of the hole and a 'climb out' button.
- [verified] Kagi's site keeps the next post's iframe loading behind the current one, so advancing is an instant transform rather than a page load. It keeps a queue of 3, refills when 2 remain, keeps 50 cached posts for Back, and uses an 8-second fetch timeout.
  => Stumble must feel instant. Prefetch and validate the next 2-3 finds, keep a Back history of about 50, and skip any source that does not answer within about 8 seconds, without showing an error.
- [verified] Kagi's inclusion rules work as a quality bar. They accept personal single-author blogs only, in English, with a post in the last 12 months. Sites must have no ads or undisclosed affiliate links, no popups (newsletter or cookie prompts), and no LLM content automation. YouTube channels must have fewer than 100,000 subscribers and post at most twice a week. Comics must be independent and not AI-generated.
  => Use these as Byways' source-selection rules and quality signals: human-made, ad-free, popup-free, small creators, recently alive. Write them into the spec as the definition of a 'good find'.
- [verified] The Kagi lists are large, human-curated and MIT-licensed. smallweb.txt has 44,185 blog feed lines, smallyt.txt has 263 channels and smallcomic.txt has 414 comics. There is a public Atom feed at https://kagi.com/api/v1/smallweb/feed/; the extension uses the variants ?nso, ?yt, ?gh and ?comic. There is also an OPML file.
  => A ready-made, legally reusable seed pool exists. The extension can fetch the feed using its host permissions. For the PWA, do not assume CORS works: ship a derived seed snapshot with attribution, and treat the live feed as an optional enhancement.
- [verified] Kagi also offers user-hidden categories (stored in a cookie), a 'flag content' action, a 'spam' category that is filtered out, and a 'River' view, which its code describes as a 'reverse-chronological card stream'.
  => Make the Mix-like feed reverse-chronological or shuffled, never ranked by engagement. Every card needs 'hide this topic', 'never this site' and 'broken or spam'; in Byways these write to a local blocklist.
- [verified] Kagi groups its topics into a compact taxonomy. Tech & Science: ai, science, programming, diy, tech, hardware, infra, web. Culture & Creative: art, design, essays, humanities, retro, photography, culture, gaming, and more. Life & World: society, life, food, travel, politics, economy, education, work, health, sports. Other: uncategorized. Spam is a separate category.
  => Offer a StumbleUpon-style interest picker with about 25 grouped topics that map onto Kagi's categories, so Tuned mode can filter that source directly. Make onboarding optional and take about 10 seconds.
- [verified] Wiby's 'surprise me' does not draw from the whole index. It picks a random URL only from pages flagged by a curator as worksafe = 1 AND surprise = 1, and its guide says NSFW sites are never shown even if flagged for surprise. Wiby also offers JSON output at /json for developers.
  => Fate mode should be pure random over a curated, worksafe 'surprise-worthy' pool, not over everything. Random over an unfiltered index produces junk.
- [verified] Marginalia's random 'Explore' draws only from curated random-domain sets plus operator-approved user suggestions; the suggestions table was added in a 2026 migration. It only serves domains whose server is currently available and that are not blacklisted. The Explore page shows a grid of site screenshots, and each card has a 'show similar websites' link based on link-graph cosine similarity (explore2.marginalia.nu).
  => Filter dead sites before showing them, using a liveness check plus a cached dead-site list. A grid of screenshot or preview cards with 'more like this' on each card is a proven pattern for the Mix-like feed.
- [likely] Marginalia's public API gateway allows browser calls from any origin: its CORS setting is origin '*' with an API-Key header and GET/POST. Keys come from its database or from Polar (paid), with per-minute and daily rate limits.
  => Marginalia search can be a bring-your-own-key source called straight from the PWA with no server. Handle rate-limit errors gracefully.
- [verified] searchmysite.net indexes only approved personal sites (about 4,000). It tries to exclude AI-generated content, shows no ads, boosts ad-free pages, and launched in July 2020.
  => This confirms a pattern across small-web tools (approved-only pools, ad-free boost, anti-AI-spam). Byways should apply the same signals when scoring AI Search and Tuned results.
- [verified] The XXIIVV webring is capped at 256 hand-reviewed sites. Members need at least 10 content pages, an about page and their own domain, and sites that need JavaScript to show their content are rejected. Sites inactive for more than 2 years may be removed, and from 2026 every member needs an 88x31 banner; members can add RSS metadata.
  => Webrings are small, high-quality, handmade pools with lists anyone can read. Include them as Fate and Tuned sources and show the webring as the reason the find appeared.
- [verified] Neocities' browse page offers sort orders including special_sauce (score, follows, views, recency), random, most_followed, last_updated, newest and featured (staff-picked).
  => Neocities is another source of handmade sites that has both random and curated (featured) views. Weight featured items higher for quality.
- [likely] StumbleUpon (founded 2001; Garrett Camp was a co-founder) was built around one toolbar 'Stumble!' button. It served a random page matched to interests the user had picked, and thumbs up / thumbs down trained future picks. eBay bought it in 2007 (reported at about $75M), and the founders and investors bought it back in 2009.
  => Keep the loved core: one button, interest steering without a feed, and thumbs that visibly change what comes next. Byways' hero action is Stumble, reachable by button, Space or voice.
- [likely] StumbleUpon closed on about June 30, 2018 and moved users to Mix (mix.com), a Camp/Expa product built around saving and following content in a card feed and collections. The reasons publicly cited were the shift of discovery to mobile and social feeds and an ageing product and tech stack.
  => Byways must work well on phones from day one (PWA plus Android), not only on desktop. It must also keep the one-button random stumble rather than turning into a feed-only product.
- [unverified] When and why Mix itself shut down could not be confirmed.
  => The spec should not state a Mix shutdown date. The general lesson (users lost their saved collections when the service ended) argues for local-first storage and easy export.
- [unverified] Users commonly say they miss StumbleUpon's serendipity: weird, handmade sites, losing hours down a 'rabbit hole', the toolbar staying inside the browser, and no need to scroll a feed. Common complaints about the late StumbleUpon and Mix: sponsored 'paid discovery' stumbles, clickbait and listicles, marketers gaming the system, repeats, dead links, redesigns that framed or wrapped sites, and Mix feeling like another account-gated Pinterest-style feed.
  => Write the design rules against each complaint: no ads or sponsored finds ever, no repeats, a dead-link check, the site's URL and creator always visible (never hide the source), no account needed, and a one-button stumble that is always available.
- [likely] Recent closures of discovery and save-for-later services, including Mozilla's Pocket (2025), Omnivore (2024) and the AI news app Artifact (2024), left users having to export or lose their saved items.
  => Byways collections must be local-first. Offer one-click export and import (JSON plus a Netscape bookmarks HTML file) and sharing by link that encodes items in the URL fragment, so nothing depends on a server staying alive.
- [unverified] Curated, high-craft one-page toys (neal.fun-style) and single-button random sites (The Useless Web) are still popular. Random-site generators built on small, fixed lists go stale: users quickly see repeats and hit dead links.
  => Prefer depth and quality over list size. Combine several curated pools (Kagi Small Web, Wiby surprise, Marginalia random, webrings, Neocities featured, Internet Archive), check liveness, and track the seen-set so a small pool never silently loops.
- [unverified] Are.na is an ad-free, subscription-funded curation tool built on user channels and connections, without public like counts or an engagement algorithm. Pinterest has drawn widespread complaints about AI-generated image spam and has added AI labels and controls.
  => Byways' social side should be calm: share collections with friends by link, with no public counters or follower metrics. Label AI-generated or AI-sourced finds.
- [unverified] Hidden-gem game discovery today relies on Steam (Discovery Queue, Curators, tags; roughly 18,000-19,000 new releases a year), Steam 250-style 'hidden gems' rankings (high rating, few reviews), itch.io browsing by tag and sort, and community lists. Common complaints are popularity bias, floods of low-effort releases, and hard-to-search archives. For the Internet Archive software library, users complain about inconsistent metadata, duplicates, and items that do not run in the browser.
  => Vault scoring should use a Bayesian-averaged rating with a minimum review count, combined with a low-download bonus, so a single 5-star review does not count as a gem. List only items that are browser-playable and worksafe. Show the reason it counts as a gem (rating, reviews, downloads, year).
- [likely] The Internet Archive suffered a breach and DDoS attacks in October 2024 and was partly unavailable for a period afterwards.
  => The Vault must handle the Archive being down. Cache metadata for gems already shown, show a friendly 'Archive unavailable' state, and keep other modes working.
- [likely] A daily puzzle that is the same for everyone (Wordle-style; the New York Times acquired Wordle in 2022) drives conversation and sharing through spoiler-free share text.
  => Daily Fate should use a date seed so every user gets the same pick. Add a 'Share today's Fate' button whose text names the day but not the find, and keep any streak gentle, with no guilt notifications.
RISKS:
- The web research ran out early. The shared WebSearch budget was already used up when this agent started (every search returned 'budget used up'), and direct fetches failed (ENOTFOUND for en.wikipedia.org, wiby.me and kagi.com). So all StumbleUpon and Mix history, user sentiment from Reddit and Hacker News, Cloudhiker, neal.fun, Are.na, Pinterest, AI discovery apps, and game-discovery complaints come from prior knowledge, marked likely or unverified. Verifying them needs a follow-up turn with more search budget (CLAUDE_CODE_MAX_WEB_SEARCHES_PER_SESSION) or those hosts allowed in the network settings.
- The Mix shutdown date and reason are unknown. The spec should not state them.
- Cloudhiker and current StumbleUpon clones could not be checked. Their feature sets and whether they are still running in 2026 are unknown.
- It is not verified whether the Kagi Small Web feed (kagi.com/api/v1/smallweb/feed) sends CORS headers. If it does not, the PWA cannot call it directly and needs a bundled seed snapshot. Its API terms of use are also unchecked (the repo's list files are MIT-licensed).
- Frame-blocking (X-Frame-Options or CSP frame-ancestors) will break iframe-based full-screen Stumble in the PWA for many sites. Kagi works around it by filtering out such sites or showing an interstitial. Byways needs the same, or a top-level navigation, per platform.
- Marginalia's CORS '*' is verified in source code only. The production config and the free-key and rate-limit terms are not confirmed from official docs.
- Turning hands-free on by default (microphone listening plus auto-reading aloud) may surprise users or feel invasive. Browsers also need a user gesture before audio can play or the mic can be used. First run needs a clear consent step and a visible listening indicator.
- AI search can return made-up or dead URLs, and AI-generated content farms are spreading. Without a liveness check and source labels, Byways would bring back the clickbait and spam problems people complained about in the late StumbleUpon.
RECS:
- Make one button the whole product. Stumble is the hero action (button, Space key, or saying 'next'), and it works with no account and no onboarding wall. Interest picking is optional, about 10 seconds, with roughly 25 grouped topics that map onto the Kagi Small Web categories.
- Make 'never twice' a promise. Keep a permanent, user-resettable seen-set of normalized URLs in IndexedDB, add a domain cooldown, and tell the user when a pool is used up instead of quietly repeating. This beats Kagi's 100-item, 1-day cookie.
- Put a 'why am I seeing this' line on every find and card: the source pool (for example Kagi Small Web, Wiby surprise, Marginalia random, a webring, the Internet Archive, or an AI model by name), the mode, and the reason ('matches retro', 'similar to X', 'Daily Fate 2026-11-11', 'pure random').
- No algorithmic doom-scroll. The Mix-like feed is reverse-chronological or shuffled and arrives in finite batches with a clear end ('That's 30 - stumble on or call it a day'). Never rank by engagement, and send no push notifications by default.
- Respect time. Offer an optional session length for lean-back mode, a gentle opt-in 'you've been exploring for 45 minutes' cue, and an end-of-session recap of saved finds.
- Quality over quantity. Draw from human-curated pools and adopt Kagi's inclusion rules as quality signals: human-made, no ads or undisclosed affiliate links, no popups, small creators, recently active, no LLM content farms. Liveness-check each find (timeout about 8 seconds) before showing it, and skip dead or slow ones without fuss.
- Make Tuned mode a transparent, adjustable blend: about 60% same-topic momentum, a small re-injection from the user's own likes, and a wildcard share. Expose it as a 'Familiar <-> Strange' control. Thumbs up or down plus 'less of this topic' and 'never this site' all edit a taste profile the user can see and edit locally.
- Make Stumble instant. Prefetch and validate the next 2-3 finds, keep a Back history of about 50, and when a site refuses framing in the PWA, show a rich preview card with an 'Open site' button instead of a blank frame.
- Use the right host per platform. The extension navigates the real tab from the toolbar button, like the StumbleUpon toolbar and the Kagi extension. The Android app loads finds as top-level WebView pages. The PWA uses iframes with a frame-blocked fallback. Always show the site's real URL and creator, and never wrap or hide the source.
- Rabbit Hole: 'more like this' excludes anything seen and shows a breadcrumb trail plus a 'climb out' button. Use local tag or text similarity offline, and AI or Marginalia 'similar sites' when available.
- Fate is pure random, but only over a curated, worksafe 'surprise-worthy' pool (the Wiby model), never the raw index. Daily Fate uses a date seed so everyone gets the same pick, with a spoiler-free share text and no guilt-driven streaks.
- Collections are local-first. Offer one-click export and import (JSON plus a Netscape bookmarks HTML file) and share-by-link that encodes items in the URL fragment, so friends can import without a server. Byways must outlive any service it uses (the Pocket, Mix and Omnivore lesson).
- Keep the social side calm, Are.na-style. Share with friends by link, with no public like counts, followers or leaderboards. Let friends exchange local blocklists and 'surprise' pools.
- Vault hidden-gem score: a Bayesian-averaged rating with a minimum review count, a low-download bonus, browser-playable only, and worksafe. Each gem card shows why it is a gem (rating, reviews, downloads, year). Cache metadata and show a friendly state when the Internet Archive is down.
- AI Search and AI team: label every AI-sourced find with the model that found it, check that each URL exists and is reachable before showing it, merge and deduplicate team results, and apply the same quality rules so AI cannot reintroduce clickbait.
- Hands-free on by default, done with consent. Show a clear first-run explanation and permission step, a constant listening indicator, a small set of one-word commands (next, back, save, more, read, stop), reader mode for reading aloud, and a dyslexia-friendly font option (a feature Kagi already offers).
- Never include sponsored, paid or ad-injected finds, even later. This was a top complaint about the late StumbleUpon. Make it an explicit design rule in the spec.
- Seed sources to list in the spec: the Kagi Small Web list (MIT; 44,185 feeds) and its feed (needs a host permission in the extension; CORS for the PWA unverified), Wiby surprise and /json, Marginalia random and API (bring your own key; CORS '*' in source), XXIIVV and other webrings, Neocities featured and random, and the Internet Archive for the Vault.
